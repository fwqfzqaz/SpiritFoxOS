# IPC 用户复制字节计数

原设计要求测量 IPC 复制开销。`SYS_IPC_STATS=25` 提供启动以来实际成功用户复制的全局累计值；这是计量接口，不改变消息大小或优化传输。当前每次复制完整 `SfMessage`（328 字节），包含固定头部/存储区，不能把计数解释为逻辑 payload 字节或成功业务请求数。

## 接口

系统调用参数为 `(output, size, reserved)`，仅 PID 1 可调用；size 必须等于 24，reserved 必须为 0。成功返回 0，并通过正常 writable-RAM 检查写出固定宽度结构：

```c
typedef struct {
    uint32_t size, version;
    uint64_t send_bytes, receive_bytes;
} SfIpcStats;
```

version 为 `SF_IPC_STATS_VERSION=1`，布局为 little-endian `<IIQQ`，偏移 0/4/8/16，大小 24、对齐 8。SDK 为 `sf_ipc_stats(out)`，shell 为 `ipc-stats`。普通应用首先返回 DENIED，不读取其参数或修改输出；根任务的非法大小/保留字段返回 INVALID，非法或只读输出返回 DENIED。

两个计数独立在 UINT64_MAX 饱和，不回绕，没有重置接口。查询只读取快照，不分配资源、不消耗端点/能力配额，也不计为一次 IPC receive。当前单核内核在同一个系统调用中取得一致快照；这里没有多核同步、每进程计数、延迟或吞吐保证。

## 哪些复制计费

- SEND：有效 SEND 能力通过后，`copy_in` 成功的全部字节计入 send_bytes。之后因消息格式、期限或满队列拒绝，已经发生的复制仍计入。
- RECEIVE：直接交付给阻塞接收者、或从队列交付时，成功 `copy_out` 的全部字节计入 receive_bytes。
- 失效/缺权限的能力、失败的输入/输出复制、没有交付的阻塞/超时不增加对应值。队列内部搬移、撤回、撤销、关闭和丢弃也不是用户复制；撤回不扣除此前已经复制的输入。
- LOG、进程创建/映像复制及统计快照自身不是此处的 IPC 复制，不计入。

队列接收现在检查输出复制结果：失败返回 DENIED，保留队首和顺序，不返回成功或计费。直接交付输出失败保留原有“接收映射发生变化”的 panic 不变量；不把它转换成正常成功。

## 验证状态

10041 项实际产品 IPC 检查以宿主复制事件日志作为独立参照，覆盖 1000 组队列/直接交付/坏格式/期限/满队列/失败复制/撤回/撤销轨迹。128 位累计参照和显式边界验证 64 位饱和；查询保护字节、完整状态不变及直接输出失败 panic 均检查。6001 项实际 core 控制检查覆盖 1000 组大小/保留参数/成功/失败输出，验证完整64位数据、保护区及普通应用先拒绝。

legacy/modern 专项观察真实计数、四次私有往返、只读输出和普通应用拒绝，并保留配额/撤回/文件 IPC、回收和磁盘字节。全局其他流量可能并行增加计数，因此 VM 往返检查至少增加一个完整消息的复制字节；精确事件相等由宿主独立事件参照验证。当前专项/完整执行状态以 PROGRESS 和 TESTING 为准，未完成验证不得作为通过发布。
