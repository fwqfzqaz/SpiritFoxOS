# 管理器身份与装载策略

2026-11-13 已整合作者 `bdd5520`，两类管理器策略分离通过本地 E1/E2 完整验证（4647.76 秒），
发布与新提交托管状态见
[实施进度](../project/PROGRESS.md)。原有账户、会话与包授权语义保持；没有增加内核身份、
公开 IPC、包格式或磁盘格式。

本次策略分层保持作者的 660 项 ABI、4096 字节 IPC、按需 mmap 装载暂存、共享内存传包、
19 项运行时导出、AHCI/NVMe 和目录遍历游标；没有恢复旧的固定暂存区或应用容量。

| 归属 | 负责什么 | 输入与边界 |
| --- | --- | --- |
| 内核 | 认证实际 PID，执行能力/页表/进程资源授权 | 不解释用户名、口令、uid/gid 或 shell 管理命令 |
| `console_policy.c` | 私有账户/四会话状态、登录登出、管理员命令门、身份快照 | 不依赖包装载、文件系统或进程创建；Root 仅取得 const 视图 |
| `launch_policy.c` | 已认证包的 kind、目录请求、native runtime 与单库元数据准入 | 不依赖账户、控制台会话、命名空间或内核系统调用；不代替签名验证 |
| `sf-init` 编排 | 隐藏口令输入与输出、创建主目录、资源租约、验证运行时进程、创建/回收应用 | 调用两类策略，保存启动时 uid/gid；会话切换不重标记已运行应用 |
| `sf-fs` | 路径权限、服务端描述与文件操作 | 使用 Root 根据实际发送者登记的启动身份；应用不能自报 uid/gid |

`SfConsolePolicy` 是管理器内部不透明类型。取得默认实例不会重置会话；仅启动时初始化。
失败初始化清除身份并拒绝授权。口令验证与会话分配仍调用作者的 accounts/session 实现；
四槽上限、最高剩余槽位重附着、隐藏输入与原 CLI 文本保持。测试夹具初始化入口仅在
`SF_HOST_TEST` 下可见。账户和会话 getter 都返回 const 视图，不能经正常客户端接口写表。

命令门保留既有精确命令/带空格参数前缀规则。未登录时只有外壳的帮助和会话查询/登录
入口可用，普通账户的管理命令在处理器运行前拒绝。外壳解析和提示属于编排，不成为包
装载器的依赖。应用启动捕获 uid/gid/会话 owner；后续登录或登出不会赋予现有应用 root。

包先经既有信任验证，再进入 `sf_launch_admit`。应用/模块实际 kind 必须匹配启动意图，
参数或环境只允许应用，委派目录要求显式 `namespace.read`，应用 runtime 必须精确匹配
`org.spiritfox.native`。单库导入继续只接受 `org.spiritfox.posix`，库包必须是模块、
relative-v1、library 角色且具有导出。进程活性、租约、暂存、映射和内核授权由 Root 编排，
纯元数据准入不能单独创建进程或增加能力。

宿主验证使用实际生产策略、账户摘要及 CBOR 解码器；真实编译负例阻止公开私有状态、
可写 const 视图和运行时夹具入口，并用禁止头文件验证两个策略没有交叉依赖。真实访客
接续账户/会话、普通账户应用准入、模块冒充应用拒绝，以及 Fs 恢复后身份保持的场景。
本地与托管检查分别记录，不把架构分层等同于全部 P0 或操作系统完成。
