# 基础优先级与等待老化

Core 0 保留单核、100 Hz 抢占和单线程进程。任务具有 0–3 的基础优先级，数值越高越优先；所有新任务，包括槽位复用后的任务，都从 1 开始，不继承创建者或旧任务的配置。

## 选择与唤醒

调度器从当前任务之后环形扫描 READY 集合，选择有效优先级最高的任务；有效优先级相同按环形顺序轮转。每等待 4 个 tick 提升一个有效级别，上限为 3，基础级别不变。刚运行的任务先清除等待时间；成功选择后开始新的等待区间。新任务在全部映射/授权完成、实际发布 READY 时记录时间，创建耗时不兑换为等待信用。IPC 直接交付、接收期限到期及端点撤销唤醒都把等待起点设为当前 tick，阻塞时间不兑换为 READY 老化。

计时只使用 tick 差，不按系统调用数量累加。极大时间差在最高级饱和，模型中的时钟回退按零等待处理，避免无符号回绕。已有用户返回栈检查和 FPU 上下文保存/恢复继续执行；选择策略不直接切换地址空间或执行任务。

最低基础级别在持续 READY 后可达到最高有效级别，再参与轮转，避免一直运行的高优先级任务永久排除它。宿主模型观察的是选择/运行间隔，QEMU 验证的是实际定时器抢占与管理器继续运行；没有把它们称为真实硬件的最坏响应时间。内核执行时间、IRQ、设备等待和 RPC 固定期限仍影响延迟。

## 配置

`SYS_TASK_PRIORITY=20` 仅允许 PID 1 调用，参数为 `(pid, level, operation)`：

- `SF_PRIORITY_QUERY=0`：level 必须为 0，返回当前基础级别。
- `SF_PRIORITY_SET=1`：level 必须为 0–3，设置并返回新基础级别。
- pid 必须是规范的 1..INT32_MAX，目标必须仍为 READY 或 BLOCKED；高位别名、非法级别/操作拒绝且不改状态，死亡/空任务返回 NOT_FOUND。

非 PID 1 的查询和设置均为 DENIED。设置不会唤醒任务、改变其等待时间、创建能力或提高新任务的默认级别。没有新增 wire 结构；原系统调用编号和 IPC/BootArgs 布局保持。

受信任串口 shell 提供：

```text
priority 1       # 查询初始管理器
priority 1 2     # 设置基础级别
priority 1 1     # 恢复默认
```

这是基础优先级和有界老化，不是 CPU 预算、实时调度、优先级继承或通用优先级上限。配置会影响已有固定期限 RPC 的等待；这些协议没有自动延长期限。继承、预算与多核仍为后续工作，作者 M7 不在本轮改动内。

## 验证

`test_scheduler` 使用实际 core 的选择和控制路径，替换硬件机制；1605642 项检查覆盖已知选择边界、同级轮转、坏返回帧、权限/高位/无副作用、槽位复用、创建中计时前进及 1000 组持续 READY 轨迹。所测轨迹最大运行间隔为 20 tick，不作为所有硬件场景的上限。原 task_new 的 8022 项检查保留，共用一个宿主夹具。

`test_sched_ipc` 直接包含产品 IPC，10000 项检查覆盖 1000 组直接交付、期限和撤销唤醒，独立检查新等待时间及基础级别保持。`qemu_priority_test.py` 在 legacy/modern 中查询/设置、拒绝非法 CLI 和普通应用自提权；每种传输四次让两个不合作高优先级任务运行，同时最低级别管理器继续运行，随后恢复配置、终止回收并验证应用、回显、挂载引用和磁盘字节。

专项和完整运行状态以 TESTING 与 PROGRESS 为准；未完成的运行不标为通过。ABI 目录仅新增系统调用和六项策略常量，前 551 项无删改，当前 558 项。
