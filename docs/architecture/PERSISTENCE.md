# 事务持久化与应用更新

本文件合并原事务持久化说明与应用更新说明，覆盖双银行提交、A/B 槽、健康确认与失败回退。

## M6 事务持久化原型

日期：2026-10-23。实现有界事务盘、持久化笔记和签名应用双槽；另有受限 Q35 IOMMU 与应用试运行确认。真实设备断电与通用文件系统仍是后续工作。`storage.img` 保持 M5 只读格式，`persistent.img` 必须以可写 virtio 盘连接。

### 提交与恢复

`services/txn.c` 同时用于宿主故障测试和用户态 sf-init。它只依赖三个回调：读 512 字节、写 512 字节、flush。成功 flush 必须使此前写入持久化；未 flush 的扇区允许丢失、乱序或撕裂。摘要检测损坏，不提供存储认证或防回滚。

每次事务完整复制最多五个文件，写入当前银行之外的另一个银行：

1. 清零备用提交记录，完成 flush。
2. 写入备用银行的全部 256 个扇区，完成 flush。
3. 写入含 generation 和银行 SHA-256 的提交记录，完成 flush。
4. 最后才更新内存中的当前文件并返回成功。

当前银行和它的提交记录始终保持不变。任何写入或 flush 失败都返回 `SF_COMMIT_UNCERTAIN (-20)`，关闭该卷的后续读写，要求重新挂载或重启后恢复。即使返回错误，新记录也可能已经落盘，所以不能承诺错误等于回滚。没有后台脏缓存；每个成功的持久化 write 都跨过完整提交边界。

磁盘驱动死亡或被 DMA 隔离后，持久化状态为 UNAVAILABLE，已打开笔记句柄与 installed 执行入口都拒绝使用离线缓存。dirty 账本仍允许释放，受控卸载与驱动重启后重新挂载恢复已提交数据；设备被内核永久隔离时仍拒绝新授权。故障诊断与验证见 `../quality/SECURITY.md`。

恢复检查两个记录的结构、保留字节、卷 ID、记录摘要、银行摘要和文件结构，选择 generation 最大的有效快照。最新快照无效时退回另一份完整快照；两份均无效或两份有效记录声称相同 generation 时拒绝挂载。读 I/O 错误同样失败关闭。generation 达到 `UINT64_MAX` 后禁止继续提交，避免回绕。

### 进程边界与持久化 RPC

`services/persistence.c`、`services/txn.c`、`services/update.c`、`services/version.c` 与约 296 KiB 的
`SfTxn volume` 常驻缓冲只链接进 `sf-persist.sfmod`；`sf-init` 不再包含事务卷，只保留
`services/persist_client.c`。磁盘格式、双银行提交顺序、A/B 槽与版本策略均未改变，因此上文
所有字节级与故障注入语义继续成立。

- sf-init 创建 `persist_ep`（服务端 RECV）与 `persist_reply`（服务端发送回复），以
  `SYS_SPAWN` 启动服务；`sf-persist` 同时持有启动包内的签名锚点策略。
- 块端点所有权：sf-init 保留自己创建的 `driver_ep` / `driver_reply` 原句柄供 Fs 块代理、写测试、
  `stop disk` 与 DMA 探测直接使用；另用 `SYS_CAP_DERIVE` 派生 `SEND|DELEGATE` 与
  `RECV|DELEGATE` 两枚子能力，随两条附加消息转移给 sf-persist，发送后立即关闭派生句柄。
- `sf-virtio-blk` 不再以发送方 PID 作为授权依据，持有服务端点 SEND 能力即为授权；这正是
  能力模型本身的语义。
- 协议是同步、有界的：ATTACH_SEND / ATTACH_REPLY / MOUNT / READ / WRITE / TRUNCATE / STAGE /
  INSTALL / BEGIN / FINISH / REVOKE / STATUS / PACKAGE / PREVIEW / REVOKED / DRIVER_DOWN。
  数据每消息最多 4096 字节（`SF_MSG_BYTES`），`READ`/`WRITE` 由客户端分块循环；`PACKAGE`/`PREVIEW`/`REVOKED`
  以 `handle` 返回总长、`length` 返回本块。`ATTACH_REPLY` 的 `handle` 被内核占用为能力字段，
  因而容量走 `offset`。
- dirty 租约由 Root 的持久化 RPC 客户端明确持有，覆盖 MOUNT（可能回退 TRYING）、
  WRITE/TRUNCATE/INSTALL/BEGIN/FINISH/REVOKE；sf-persist 内部的 transaction 回调仍是 no-op。
  SEND 被内核拒绝或收到认证完成回复后释放。已认证的 COMMIT_UNCERTAIN 表示服务已完成
  但磁盘结果不确定：关闭卷、释放账本，按原盘重挂载恢复。没有认证完成的超时/坏回复则
  保留 DIRTY，拒绝后续卷 RPC 和新包执行，不能通过命名空间重建清账，需要重新启动系统；
  一般持久化进程恢复属于 P1，不承诺此处已实现。
- `unmount /disk`、`stop disk`、crash/dma 测试在驱动失效后通知 `DRIVER_DOWN`；
  `start disk`、`mount /disk` 重新派生并转移能力，再执行 MOUNT 恢复卷。
- `/persist` 与 `/persist/notes` 现在是客户端投影：`external_read` 对 `index!=UINT32_MAX`
  继续委托 readfs 的磁盘读取，其余分块走 `OP_PERSIST_READ`；写入与截断只接受 NOTES 索引。
  节点 `size` 仍由命名空间在成功外部写入后更新。
- 挂载成功后用 `OP_PERSIST_REVOKED` 把 `/boot/revoked` 的完整有界快照同步回 sf-init；
  八个32字节 ID 一次返回，在副本验证后原子合并。`revoke-key` 已确认提交后要求再次
  同步；失败关闭新包权限，语义与缓存恢复见下文和 `TRUST.md`。
- `staging` 装载暂存区仍是所有用户映像的唯一入口，扩为 512 KiB；`sf-persist` 的
  `.bss`（349 KiB）必须容纳在该容量内。当前暂存区已随通用 Fs 扩为 1280 KiB，
  实际 ELF 页对齐装载大小和 2 MiB 可写预算均由构建/归属检查门控。

### 已挂载卷的只读元数据与重投影

`OP_PERSIST_NOTES_SIZE=103` 只查询已验证、仍在线卷中的 `/notes/user` 长度，缺省文件返回 0；
未挂载、事务不确定或驱动离线返回 `SF_DEVICE_GONE`。它不读写块设备、不重挂卷、不运行
试运行恢复，也不改变暂存包、导出缓存、信任撤销集合或 generation。服务只接受实际 RECV
发送者 PID 1，核对内核发送者字段、版本、完整载荷大小、操作号、非零请求编号与空参数；
不接受附加能力。客户端独立核对回复 PID/编号/操作号/头部/期限、空字段、状态及 16 KiB
长度上限，错误不修改调用者输出，并关闭意外收到的能力。共享消息和磁盘布局保持。

`sf_persist_reproject(ns)` 先查询上述元数据，再把 `/persist` 与 notes 节点原子发布到空目标
命名空间并安装已有后端钩子。目标被占用、回复不合法或离线时保留原树；它不调用
`OP_PERSIST_MOUNT` 或同步信任。真正的磁盘重挂载仍使用原 MOUNT 流程：该流程在看到
TRYING 时会提交回退，不能用来恢复单独重建的易失命名空间。`persist` 管理诊断通过真实
RPC 额外显示 `notes-bytes` 或 `notes-unavailable`，普通会话的管理门保持。

该接口作为 P0 进程拆分的前置交付。后续工作树已接入独立 Fs，真实死亡/重启和
TRYING 保持的最新验证状态见 NAMESPACE 与 PROGRESS，不能用此前元数据单项替代完整门禁。宿主用实际签名包和生产事务/更新/持久化实现进入 TRYING，逐字节比较卷、
交易银行、暂存/导出缓存与撤销集合；真实访客覆盖 PENDING/STABLE 的查询与离线/重挂载。
TRYING 的真实访客恢复仍需后续跨进程迁移场景，当前不以宿主结果替代。

### 固定磁盘布局

全部整数小端，容量必须恰为 4096 个 512 字节扇区（2 MiB）：

| LBA | 内容 |
| --- | --- |
| 0–2047 | SFRFS1 头、目录、只读签名包；文件必须完全位于这个区间 |
| 2048 | 不可变事务几何头 |
| 2049 / 2050 | 银行 0 / 1 的提交记录 |
| 2051–2306 | 银行 0，128 KiB |
| 2307–2562 | 银行 1，128 KiB |
| 2563–4095 | 保留，不写入 |

几何头：magic[8]=`SFTXN1\0\0`，version:u32=1，sectors:u32=4096，volume_id[16]，reserved[448]=0，sha256[32]。最后摘要覆盖前 480 字节。格式化工具从只读区域内容派生卷 ID；现阶段不把卷 ID 当作认证。

提交记录：magic[8]=`SFCMT1\0\0`，generation:u64，bank:u32，reserved:u32=0，volume_id[16]，bank_sha256[32]，reserved[408]=0，sha256[32]。记录所在槽和 bank 必须一致。

银行头位于前 512 字节：magic[8]=`SFBANK1\0`，generation:u64，count:u32，reserved[492]=0。紧接五条 128 字节记录：path[64]、bytes:u32、reserved[28]=0、content_sha256[32]；记录区结束于偏移 1152（512+5*128），每个记录对应从银行偏移 `1152+i*16384` 开始的固定 16 KiB 数据槽，记录区与数据槽不重叠。未使用记录、数据尾部与银行剩余空间全零。路径是小于 64 字节的 NUL 结尾 ASCII 绝对名，拒绝空分量、点路径、反斜线和重复名。这是固定键集合的快照，不是完整目录树文件系统。

`tools/package/mkpersist.py` 只格式化新构建镜像，写入空 generation 1；系统不会自动格式化无法识别的盘。重新构建会重建 `build/persistent.img`，实际使用时先复制为自己的工作镜像。

`python3 tests/qemu/qemu_test.py --interactive --persistent` 会在首次运行时创建 `build/user-persistent.img` 并以可写盘启动，以后复用这份副本。重新构建不会删除该副本；它仍受创建时的包签名公钥约束。

### 设备与命名空间

BootArgs 保持 96 字节：尾部由 `device_bdf:u32` 细分为 `device_bdf:u16,device_rights:u16`；装载计划原保留字段成为 `device_rights`。ABI 1 仍是开发中接口，旧驱动包不构成二进制兼容承诺。只有根进程能创建带设备授权的任务；未知权利以及无设备的写授权被拒绝。

默认驱动只接受只读介质。根服务可以给驱动显式 `SF_DEVICE_WRITE`，此模式要求设备可写并提供 `VIRTIO_BLK_F_FLUSH`，协商 FLUSH 后才能提交。只有 SFRFS1 文件不越过 1 MiB、事务几何与快照均验证成功，才启用 LBA 2049–2562 的写范围。这是可信块协议中的写边界；即使使用可选 VT-d 限制 RAM DMA，也不限制恶意驱动重新编程磁盘扇区写入。DMA 模式见 `IOMMU.md`。

OUT 请求通过两个严格有序的 256 字节消息组装。FLUSH 使用类型 4、sector=0、没有数据描述符；状态与队列完成仍经过校验。普通应用没有驱动端点、端口或 DMA 映射。

`/persist/notes` 映射到事务键 `/notes/user`，支持普通 open/read/write/seek、显式 truncate 和独立偏移，最大 16 KiB。每次 write 保留原文件未覆盖的尾部，与 RAMFS 一致，不隐式截断；truncate 缩短或补零扩展，同长度请求不写盘，保持打开偏移。改变长度使用同一双银行提交与 dirty 账本，语义及故障回归见 `NAMESPACE.md`。打开文件持有 `/disk` 文件系统引用，卸载失败会恢复准入。其余键为 `/slots/a.sfk`、`/slots/b.sfk`、`/boot/current`、`/boot/revoked`，没有授予普通文件写接口。普通 run 没有文件根；显式 runat 可按签名请求授予只读目录，不能据此写入或截断笔记。

`/persist` 目录禁止创建其他文件，避免把 RAMFS 文件误认为持久化数据。卸载同步移除这两个投影节点；重新挂载从盘恢复。

### 签名应用双槽

```text
write /persist/notes durable-note
cat /persist/notes
install /disk/bin/diskhello.sfk
run installed
persist
```

install 固定源包快照，验证现有根公钥的 Ed25519 签名、应用类型、native 运行时和 ABI 1。包上限 16 KiB。备用包槽及 PENDING 选择记录在同一事务内提交，最后 flush 成功才输出 `install: COMMITTED`。每次启动 installed 都重新验证签名，再上传相同快照给隔离 native 运行时独立复查。文件摘要重新计算也不能让坏签名获得执行权限。

现在支持持久化试运行标记、按时退出 0 后确认、失败及中断后选择器回退，并保护 app_id 和包摘要。已确认包的签名版本形成软件下限，拒绝降级/同版本换包，精确重装不写盘。160 字节选择记录、旧格式迁移、版本策略与精确健康边界见 [应用更新](PERSISTENCE.md)。没有独立可信版本计数、TPM 防回滚或多应用包管理器。银行是完整卷快照；A/B 文件是应用更新槽。五文件、每文件 16 KiB 是明确的原型配额。

### 签名锚点与密钥撤销

包验证采用最多八个用途受限的构建时公钥，默认模块、应用与备用应用三个锚点。`services/trust.c` 在不可变策略之上叠加最多八个运行期撤销 key_id；`SF_REVOKED` 与 `SF_BAD_SIGNATURE` 分开返回，诊断能区分"签名无效"与"签名者已被策略拒绝"。

`revoke-key /disk/bin/app.sfk` 固定磁盘包快照，要求其携带任一有效锚点签名，然后撤销其签名者并把 key_id 以 32 字节条目追加到事务键 `/boot/revoked`，与普通事务一样经过双银行提交与设备 flush。重复撤销返回 UNCHANGED；包路径不存在、非包或签名无效按对应错误码拒绝。撤销状态在挂载时、任何包重新验证之前加载，因此重启后立即生效。被撤销签名者的既有槽位包在状态记账时仍证明完整性，但执行入口重新验证时按 `SF_REVOKED` 拒绝。`trust` 命令显示锚点数、撤销数与已撤销 key_id 前缀。

撤销不等于撤销已发生的外部副作用，也不阻止离线重放撤销记录生成之前的旧盘快照；结合软件版本下限与签名锚点约束才构成当前原型的更新策略边界。生产密钥管理、密钥离线轮换流程与可信防回滚仍是后续工作。

### 验证依据

宿主在 261 个写/flush 操作边界分别注入丢失、部分持久化/撕裂、已持久化但返回错误，共 783 个失败场景。每次模拟崩溃再挂载，两个关联键只能同时是旧值或同时是新值。另测成功提交、损坏银行回退、两份损坏拒绝、相同 generation 拒绝、非法路径、超大文件和 generation 溢出。

QEMU 测试使用镜像副本，覆盖文件和 A/B 安装重启、卸载/重启驱动后重新挂载、存储摘要正确但签名错误的槽、银行损坏回退、实际 OUT/FLUSH EIO，以及写入银行中段时由 blkdebug 暂停后强制终止 QEMU，再启动恢复。只读底区和原始构建镜像摘要必须不变。进程终止测试不等于宿主机或物理盘断电测试。

协议参考 [OASIS virtio 1.1](https://docs.oasis-open.org/virtio/virtio/v1.1/virtio-v1.1.html) 的块设备 FLUSH 语义；错误注入依据 [QEMU blkdebug](https://www.qemu.org/docs/master/devel/testing/blkdebug.html)，暂停状态通过 [QMP query-status](https://www.qemu.org/docs/master/interop/qemu-qmp-ref.html#command-query-status) 确认。

### 原始四记录 v1 银行兼容

原始 SFTXN1/SFBANK1 v1 使用四条 128 字节记录，数据槽从银行偏移 1024 开始；当前写出格式有五条记录，数据从 1152 开始。两者的版本字段相同，不能仅根据版本值假设几何。读取器在验证提交记录与完整银行摘要后，接受两种精确几何，并分别检查路径、唯一键、保留字节、内容摘要、未用记录/槽和尾部零填充。格式错误仍拒绝该快照，保持另一完整有效快照的恢复规则。

最高有效 generation 在两种几何之间统一选择，同 generation 的两份有效记录仍拒绝歧义。原本“有效旧银行被当作损坏而回退到更早空银行”的情形已经修复；原始四个文件完整导入五槽内存结构，剩余一槽可用于 /boot/revoked。

事务挂载/解码本身只读，不进行后台改写。下一次普通提交写入备用银行的当前五记录布局，沿用 261 个操作边界和原 flush/提交记录协议；旧完整快照保留到普通提交成功。若上层因未确认试运行而进行既有恢复提交，该次正常提交同样写出当前布局。此兼容不提供可信版本计数、旧盘回放防护或签名策略放宽；已安装包仍独立通过签名、用途、撤销与版本检查。

本轮完整验证通过：1112.0 秒、157 VM；2046559 项兼容宿主断言含一千个旧/混合快照与 783 个首次迁移故障场景。六次真实 VM 验证四键旧盘稳定只读访问字节不变、笔记/双槽/版本保留、普通写迁移、第五撤销键和重启；详细记录见 ../quality/TESTING.md。

## 应用更新试运行与恢复

本阶段只管理一个 native 应用的双槽更新。它在用户态运行，复用 M6 双银行事务，不改变 Core 0 或 EFI 启动槽。包上限 16 KiB，按镜像内有界信任库认证；默认使用独立的应用开发公钥，模块开发公钥默认不能签应用。旧单密钥迁移和扩展应用公钥的重叠轮换/撤销见 `TRUST.md`。

### 使用与状态

```text
install /disk/bin/diskhello.sfk
persist
run installed
persist
```

安装验证签名、应用类型、ABI 1、native 运行时及非空应用身份，再把备用包与 PENDING 状态一起提交。最后一次设备 flush 成功后才返回 `install: COMMITTED`。此时只是待试运行；后续安装返回 BUSY，以免覆盖已确认的回退包。

`run installed` 和 `run /installed.sfk` 使用相同流程：

1. PENDING → TRYING 的记录先完成事务及 flush，才允许装载应用。
2. 选择记录中绑定的包 SHA-256，每次加载验证摘要、签名和 app_id；native 服务再次验证上传的同一快照。
3. 应用在现有 300 tick 截止时间内正常退出且状态为 0，再提交 STABLE，才输出 `update: CONFIRMED` 与 `sfexec: exit 0`。
4. 验证/装载失败、进程异常、非零退出或超时，提交 STABLE 并保留原来的已确认槽，输出 `update: ROLLED BACK`。第一次安装没有已确认槽时回到未安装状态。

PENDING 重启后仍待用户运行。TRYING 表示已尝试但没有持久确认；挂载时先提交回退，再公布 `/persist`，输出 `update: RECOVERED interrupted trial`。正常启动不会自动执行待更新包。已确认应用的后续运行不新增健康度事务。

任何状态事务的写入或 flush 失败均沿用 `SF_COMMIT_UNCERTAIN`，关闭卷准入。运行成功但确认事务失败也返回错误，不能声称更新已确认。重启后可能看到旧记录或完整新记录：TRYING 回退，完整且已确认的 STABLE 保留。恢复提交再次失败时拒绝持久化挂载，不继续尝试执行。

### 选择记录

四个事务键仍是 `/notes/user`、`/slots/a.sfk`、`/slots/b.sfk`、`/boot/current`。最后一个键改为 160 字节的规范记录：

| 字节偏移 | 内容 |
| --- | --- |
| 0–7 | `SFUPD1\0\0` |
| 8 | phase：0 STABLE、1 PENDING、2 TRYING |
| 9 | 已确认槽：0、ASCII a 或 b |
| 10 | 候选槽：0、ASCII a 或 b |
| 11–31 | 全零保留字节 |
| 32–63 | 已确认包 SHA-256；没有槽时全零 |
| 64–95 | 候选包 SHA-256；没有槽时全零 |
| 96–159 | NUL 结尾且尾部补零的 app_id，最长 63 字节 |

app_id 只接受 ASCII 字母、数字、点、下划线和连字符。STABLE 不得有候选；PENDING/TRYING 必须有候选且不同于已确认槽。空状态不得有身份或摘要。未知 phase、非法组合、非零保留或尾部填充均拒绝。

已确认应用存在时，后续候选必须具有相同 app_id。候选包与状态在同一事务提交，试运行固定到该摘要；另一个正确签名包也不能直接替换它。旧版单字节 a/b 记录可读取：先认证所选包，导入为已确认状态，下一次实际升级写入新格式；精确重装仍不写盘。错误的旧包不会被默认信任。

### 已确认版本下限

已安装应用采用有界的数字版本策略：`major.minor.patch`，每段为 0 到 4294967295 的十进制整数；除单个 0 外禁止前导零，不接受前缀、空格、预发布或构建后缀。按三个整数依次比较，`1.2.10` 高于 `1.2.9`。此限制只用于持久化安装及 installed 启动，不改变通用包容器的版本字符串格式。

版本下限来自当前已确认包内的签名清单，先认证包摘要、签名和 app_id 再读取，不添加第二份可能与健康状态不一致的可写计数器：

- 更高版本可提交候选，仍需试运行确认。候选失败或中断时，回退保留旧包及旧下限。
- 更低版本，以及版本相同但包 SHA-256 不同，返回 `SF_VERSION_REJECTED (-21)`。
- 当前已确认包的精确重装输出 `install: UNCHANGED`，不写盘、不切槽、不重新试运行。
- 安装被拒绝不改变卷 generation。确认事务成功后，新的已确认包就是新的下限；确认写/flush 失败仍执行卷的失败关闭及重启恢复规则。

`persist` 显示经认证的 `confirmed-version=... policy=monotonic`；认证失败显示 unavailable 和错误码，不能显示未经认证的版本。执行候选时再次检查版本，以覆盖旧实现留下的 PENDING 记录；不合策略的候选不会执行，按既有健康失败流程回退。

例：`diskhello.sfk` 为 0.1.0，`diskupdate.sfk` 为 0.2.0，`disknext.sfk` 为 0.3.0。安装并确认 0.2.0 后，0.1.0 被拒绝；0.3.0 试运行失败仍允许另一个 0.3.0 候选，健康确认后才拒绝相同版本的不同内容。

### 范围与验证

健康标准是当前有界命令应用的“按时退出 0”，不是长期服务的就绪、业务正确性或生产健康策略。成功确认后的程序在未来一次运行失败，不会自动撤回已确认版本。版本下限只防止持久化安装与 installed 路径的软件降级；直接运行只读盘上另一个包仍是显式独立操作。没有独立可信单调计数、在线信任策略更新、TPM 防回滚、系统/内核双槽或多应用管理。

回退只恢复应用选择器。控制台输出及未来可能加入的文件、网络、数据库副作用不能由选择旧包撤销；本阶段未提供跨应用数据事务或 schema 迁移保证。磁盘摘要不提供离线存储认证；攻击者恢复整份旧磁盘镜像的行为不在此防护范围内。银行损坏后若恢复较早的完整快照，软件版本下限也以该快照中的已确认包为准，不能充当独立硬件防回滚计数器。

`tests/host/test_update.c` 把实际状态机与事务引擎组合，覆盖 stage/begin/confirm/rollback 四个提交点，各 261 个操作边界 × 三种故障模式，共 3132 个失败场景，并验证恢复记录与槽摘要一致、未确认尝试不能变成已确认版本。规范编码、截断、保留字段、身份、重复试运行和首装失败另有检查。

`tests/qemu/qemu_persist_test.py` 在 legacy 和 VT-d/modern 下分别验证实际应用页故障、退出 42、死循环超时、首装失败、待更新保护、身份/摘要/签名拒绝、旧格式迁移、非法状态拒绝、试运行期间终止 QEMU 后回退，以及应用退出 0 后确认写 EIO 不被误报成功。它们不等同于物理断电或任意硬件验收。

`tests/test_version.c` 另有 4069 项检查，覆盖严格数字版本、整数溢出、大小比较、相同版本的摘要约束和 1000 次固定种子往返。QEMU 还覆盖版本确认后重启保持、失败候选不提高下限、幂等重装和拒绝操作字节不变、四种已签名非法版本，以及旧 PENDING 降级/同版本换包/非法版本的启动拒绝。

### 调用预检与待试运行候选

run installed 及 /installed.sfk 别名现在在写 TRYING 前检查 native 登记、进程和服务端点是否可用。runat/runenvat 还对认证有效的候选检查 namespace.read 声明；不支持目录委派的有效应用拒绝本次调用，候选仍保持 PENDING，可用正确形式重试。

| 情况 | TRYING 前处理 | 待执行候选 |
| --- | --- | --- |
| native 停止、排空或死亡 | 返回 STALE_HANDLE、DRAINING 或 DEVICE_GONE | 保留，磁盘不变 |
| 有效包没有 namespace.read，但调用要求目录 | 返回 DENIED | 保留，磁盘不变 |
| 目录不存在、词法/argv/env 非法 | 保持原有预检错误 | 保留，磁盘不变 |
| 候选摘要、签名、身份、版本或清单无效 | 进入既有试运行/装载失败路径 | 回退已确认包 |
| 预检后实际装载/执行失败 | 保持既有健康判定 | 回退已确认包 |

内部 sf_persist_preview 只读认证 PENDING 候选，使用候选槽、候选摘要以及已有版本下限；它不提交状态，也不直接提供执行授权。正常 sf_persist_package 仍拒绝 PENDING，实际装载必须在 TRYING 持久化后重新认证。预检认证错误留给原装载路径处理，避免把坏候选永久留在 PENDING；只有有效包不支持本次调用才提前拒绝。

预检不预留进程/端点/设备资源，也不能保证之后仍可用；后续失败仍按原规则回退。事务格式、版本下限和双槽健康确认协议保持。

`tests/host/test_version.c` 另有 4069 项检查，覆盖严格数字版本、整数溢出、大小比较、相同版本的摘要约束和 1000 次固定种子往返。QEMU 还覆盖版本确认后重启保持、失败候选不提高下限、幂等重装和拒绝操作字节不变、四种已签名非法版本，以及旧 PENDING 降级/同版本换包/非法版本的启动拒绝。

旧四记录事务银行中的双槽与选择记录会在解码时完整保留，保持认证后的身份、摘要、版本下限和试运行状态。仅事务几何在下一次正常提交时升级；稳定只读调用不触发迁移。格式与失败恢复规则见 [PERSISTENCE.md](PERSISTENCE.md)。

## 管理器对普通持久化回复的边界（2026-11-13）

`pf_call` 对变更、元数据与普通读取均检查实际 PID、请求号、完整协议头、操作码、
关联 deadline 和有界 64 位状态，之后才转换成 int。任何回复附加能力先关闭接收引用，
再拒绝该回复。READ 返回的 length 不得超过本次请求或消息数据区，offset 保持，
handle/mode 为零；正常短读与 EOF、原有语义错误保持。损坏回复不能把声明长度直接
交给读取缓冲区，也不能通过 2^32 状态窄化假装成功。

这不改变变更请求的不确定完成策略：没有认证完成仍保留 DIRTY，后续卷访问与安装
失败关闭；错误不保证没有发生写入，不自动重试或重放。Stage/export 跨回复进度/总量、
attach ACK 与一般 Persist 重启没有在此轮一起改写。宿主畸形回复和实际访客正常读取
分别提供 E1/E2 证据，不能据此声称发生了提权、披露或完成真机/长期验收。

## 上传、附着 ACK 与包导出的有界进度（2026-11-13）

Root 在上传前拒绝空包（BAD_FORMAT）、非空 NULL 输入（INVALID）和超过既有事务
单文件 16384 字节的包（NO_SPACE）。空上传不再被视为完成，INSTALL/REVOKE 因而不能
沿用 provider 中上次的暂存包。此上限来自事务文件格式，未缩小一般应用镜像或 mmap
暂存。STAGE 成功回复必须保留本次 offset、完整 length、零 handle/mode；负语义错误
仍原样返回，失败不自动重试。只有收到完整块 ACK 才推进下一块。

attach ACK 检查实际发送者/请求号、完整头、关联 deadline、无附加能力、有界 64 位
状态和成功时的 offset/mode/零 length。输入能力在发送成功/失败、超时、耗尽及拒绝
路径关闭一次；意外回复能力也先关闭。cap_count=0 时 handle 是 provider-local 信息，
不能当成 Root 的能力关闭。没有因此新增恢复、自动重放或一般 Persist 重启协议。

PACKAGE/PREVIEW 的总长度先验证为事务单文件范围，再比较输出容量，且一次导出中
总量固定；每块必须保留 offset、零 mode，并精确返回 min(剩余字节, 消息容量)。
所有界限在 memcpy 前验证，零导出不进行 NULL 指针算术；容量不足返回 NO_SPACE。
若后续块失败，已验证前缀可能已写入，返回错误并停止，不保证全部输出区未变。
合法包最多四块。分块加固本身不改变信任缓存；后续独立的单消息原子同步见下节。
写操作未知完成保持原有 DIRTY 失败关闭，不改事务、信任根、签名或公开 ABI。

## 运行期撤销快照与准入就绪

`REVOKED` 的既有服务端语义不变。客户端固定请求 offset=0，一次读取最多256字节；
完整头/发送者/编号/期限/状态及意外能力已由通用 RPC 验证，再检查返回 offset=0、
mode=0、handle 总量为32的倍数且不超过256、length 恰等于 handle。没有循环等待
零进度的路径。逐 ID 在 `SfRuntimeTrust` 副本上调用实际撤销实现，完整成功后才替换
缓存；旧列表和空列表保留已经观察到的撤销，不恢复签名权。并集超出八项返回
NO_SPACE 并保持故障，较短的后续快照不能清除它；需要新的可信上下文。

`sf_persist_security_error()` 先报告原未知写完成，再报告独立信任就绪错误。初次
挂载/已知撤销提交之后要求同步；收到畸形或不完整列表也关闭新权限。Root 的所有
包获取入口与客户端安装/撤销/BEGIN 在新增权限或写 TRYING 前检查就绪。这里不是
撤销已运行任务，也不停止已有数据访问或 FINISH 清理。正常 `trust` 查询遇短暂离线/
超时可保留最后可信缓存，完整有效的显式同步能修复非容量故障，不能清除 DIRTY。

REVOKE 成功 ACK 后的同步错误可能发生在磁盘提交之后。返回同步错误不表示撤销
没有生效，也不把已确认提交变为不确定写；先查询/修复信任，再核对实际状态，不能
自动重放。新测试用签名故障服务验证该时序及 Root 的 PENDING 屏障，见 TESTING。

## 持久化服务到块驱动的回复边界

Persist与Root使用同一私有完整回复验证器；负服务错误保持，错关联/畸形帧使本地
驱动会话失效并在扇区复制前返回错误。收到的能力回收、请求号耗尽拒绝和各成功
载荷长度见 `STORAGE.md`。这里不修改事务卷、签名、扇区桥或Root的DIRTY账本。

双传输实际故障服务测试分别覆盖Root只读降级与Persist挂载失败后的信任屏障，再
显式卸载/重建驱动或重新附着恢复。已有只读notes-size缓存不是硬件健康查询，驱动
死亡后可仍返回最后已提交长度。故障READ与恢复不改已提交笔记/盘字节；这不证明
发送后的WRITE/FLUSH已取消，也不扩展未知写完成的保证。
