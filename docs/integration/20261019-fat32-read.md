## 接口与顺序

模块 ABI 仍 1.5，块协议仍 v2，没有增加模块权限或改变包布局。
新增 kernel-only `block_client.h`：open 通过 GET 固定 endpoint/snapshot、槽号、
扇区大小和容量，检查记录版本、来源/类型及几何；挂载后不静默重新绑定新代数。
read 单次最多 64 KiB，拆成最多 4096 字节的 READ。每段检查 transport 返回值，
再检查身份、sequence、snapshot、LBA、result 和 size，全部一致才复制。
结构有效的输出范围在请求前清零；任一段失败再次清零整个范围，不交付部分成功。
缓冲指针、count、容量等结构性错误不会触碰无法确认安全的输出地址。

每次 RPC 前清空 response，不能依赖 sfm_call 在拒绝旧端点/忙时清空输出。
调用时保存/关闭本 CPU 中断，RPC 后恢复原状态，避免同步 handler 被本 CPU 抢占。
EBUSY/EAGAIN 立即返回，零次自动重试；不睡眠、不无限轮询、不绕回原始读取。
跨 CPU 冲突仍可失败，未承诺可睡眠 IPC 或 SMP 并发成功率。
动态内存分配在 RPC 关中断区外；底层 AHCI 硬件轮询的延迟限制仍在。

调用链为 FAT32 -> block_client -> dev.block READ -> 核心 bounce page -> blkdev/AHCI；
后端不调用 FAT32/VFS，因此没有文件系统消息递归。封存先于 vfs_init 和 FAT32 挂载。
旧 dev.block 卸载/重建后，原挂载的客户端报错，不自动切换到新设备或 raw 读。

## FAT32 接入与错误处理

- BPB、簇、FAT 表项、原写路径的读改写预读，已全部使用客户端；fat32.c 无 blkdev_read。
- 挂载先 GET 再读 BPB，核对实际扇区大小、总扇区/数据区、FAT 容量、根簇，拒绝零/非
  2 次幂簇大小、溢出布局、未支持的活动 FAT/版本；只支持镜像模式 FAT。最大簇 64 KiB。
- 所有簇缓冲按实际大小连续分配，逐页释放，避免旧固定 4 KiB 缓冲溢出。新目录整簇清零。
- FAT 表查询改为 status + out，I/O/OOM 不再伪装 EOC。所有调用方先检查错误再解析。
  文件读失败清空本次有效输出范围，不推进 offset；短链不报告正常 EOF。
- 目录链遍历以卷簇数为上限，递归深度最多 64；目录读失败使挂载失败并回收本轮树。
- 启动检查要求 BPB/目录与实际文件读取的专用标记，保留用户程序执行和 Wayland 检查。

## 限制与下一步

WRITE 消息仍 EROFS；兼容 FAT32 写入仍直接 blkdev_write，未迁移写权限、事务、多个 FAT
副本一致性、断电恢复或超时写 DMA 生命周期。不能称系统只读或磁盘写保护。
只读传输错误隔离 DMA 页沿用上一轮；没有控制器复位/热恢复。其他直接块 I/O 仍需审计。
当前模块是可信 Ring 0，不具备地址空间/驱动崩溃隔离。真机与多 CPU 压测未完成。
下一步先处理原 FAT32 写入缓冲的 DMA 生命周期与错误传播，再设计受限写桥；详见 NEXT。
