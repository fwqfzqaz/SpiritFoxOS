## 审计与接口决定

实际 blkdev_write 调用者原为 FAT32 的簇写、FAT 表写两处；devfs 块节点写仍未实现。
原写缓冲是 FAT32 临时物理页，AHCI 超时返回后立即释放可能让控制器继续读取已复用内存。
读取桥的永久页没有保护这个路径。本轮两处均改用内核私有兼容写入器，fat32.c 无直接
blkdev_read/write。blkdev_write 仅作为平台适配器的底层派发，不反向调用文件系统。

新增 kernel-only sf_block_client_write_compat：固定已有卷的 snapshot、槽、扇区大小与
容量，必须封存且匹配当前 dev.block 代数及实际平台几何；最多 64 KiB，拆为 4 KiB 写。
不新增模块 API 或权限，模块 ABI 仍 1.5、块协议仍 v2，WRITE RPC 仍 EROFS。
这是受信任内核兼容入口，不是能力认证/用户态驱动协议，也未承诺整个块 I/O 已消息化。

每设备分别持有永久读页和永久写页，最多 128 KiB；按设备共享 try-lock 和失败标志。
整个有界写请求持有该设备锁，本 CPU 中断状态按原值恢复；其他设备不共用忙标志。
每段先清零写页、复制源数据，再派发物理驱动；调用方的页从不直接作为写 DMA 源。
completed 返回已完整成功的段所含扇区数，不包含失败段；失败段本身也可能已部分写盘。
EBUSY 意味后端未发命令，不隔离，可由外层决定重试；本接口没有自动重试或睡眠。
其他后端错误统一 EIO，读写两向均停止，该设备的两个页不再复用/释放。没有热恢复入口。
OOM/参数/旧快照/未知几何在提交硬件前失败；不能把 busy/完成前缀说成事务或回滚保证。

## FAT32 接入

- 以卷的 try-lock 串行化 write/create/mkdir/unlink，不自旋、不睡眠，也不整段关中断等待锁。
  底层硬件轮询仍有本 CPU 关中断区间；没有进行 SMP 长期压力或并发读快照隔离验收。
- 文件写遇到数据、FAT 链或目录项错误返回负码，不再吞错返回成功；全部成功后才更新
  内存 start_cluster/size/offset。磁盘上已写的前缀不会因此回滚，失败不是“磁盘未变”。
- 已发生修改后再失败，以及硬件 I/O/分段写失败，会使该挂载拒绝进一步修改（EROFS）。
  首段纯 EBUSY、修改前 OOM/非法参数不使健康卷进入此状态。读是否继续取决于核心 I/O 隔离。
- 零长度写不分配簇；超大返回值/32 位文件大小溢出拒绝。暂不支持越过 EOF 的稀疏写，
  明确拒绝，避免暴露未初始化空洞；没有顺带实现截断/稀疏文件语义。
- 新簇先预分配缓冲、保留 FAT 槽并完整清零，最后链接到旧链。清零/链接失败不发布簇号，
  不在失败设备上盲目回滚，可能保留孤立已分配簇，后续需要离线修复。
- 镜像模式（ext_flags=0）成功时更新所有 1–2 份 FAT，分别保留高 4 位；跨副本失败
  直接报错并禁止后续修改，不能承诺失败时副本一致或断电一致。
- mkdir 发布失败不再盲目释放不确定簇；unlink 的目录删除失败后绝不释放仍被引用的链，
  清链逐项检查错误并设上限。打开后 unlink、LFN 删除与完整 POSIX 生命周期尚未重构。

## 继续入口与边界

没有 FLUSH CACHE/持久化接口、日志或事务；写命令完成不等于断电后数据已落盘。
后续优先做显式选择的可丢弃 FAT32 镜像写入/重启/fsck 验证，再设计 flush、恢复策略和
受限写消息授权。不要默认在真实附加盘启动自测写入，不把故障后 EROFS 等同只读挂载。
仍可信 Ring 0；HBA 复位、取消 IPC、IRQ/DMA 代理、用户态隔离和真机验收未完成。

用户本轮恢复额度保护：任一可用额度窗口剩余少于 5% 时保存进度并停止，等待指示。
