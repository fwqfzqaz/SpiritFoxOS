# 应用更新试运行与恢复

本阶段只管理一个 native 应用的双槽更新。它在用户态运行，复用 M6 双银行事务，不改变 Core 0 或 EFI 启动槽。包上限 16 KiB，仍使用工作区的开发公钥。

## 使用与状态

```text
install /disk/bin/diskhello.sfk
persist
run installed
persist
```

安装验证签名、应用类型、ABI 1、native 运行时及非空应用身份，再把备用包与 PENDING 状态一起提交。最后一次设备 flush 成功后才返回 `install: COMMITTED`。此时只是待试运行；后续安装返回 BUSY，以免覆盖已确认的回退包。

`run installed` 和 `run /installed.sfk` 使用相同流程：

1. PENDING → TRYING 的记录先完成事务及 flush，才允许装载应用。
2. 选择记录中绑定的包 SHA-256，每次加载验证摘要、签名和 app_id；native 服务再次验证上传的同一快照。
3. 应用在现有 300 tick 截止时间内正常退出且状态为 0，再提交 STABLE，才输出 `update: CONFIRMED` 与 `sfexec: exit 0`。
4. 验证/装载失败、进程异常、非零退出或超时，提交 STABLE 并保留原来的已确认槽，输出 `update: ROLLED BACK`。第一次安装没有已确认槽时回到未安装状态。

PENDING 重启后仍待用户运行。TRYING 表示已尝试但没有持久确认；挂载时先提交回退，再公布 `/persist`，输出 `update: RECOVERED interrupted trial`。正常启动不会自动执行待更新包。已确认应用的后续运行不新增健康度事务。

任何状态事务的写入或 flush 失败均沿用 `SF_COMMIT_UNCERTAIN`，关闭卷准入。运行成功但确认事务失败也返回错误，不能声称更新已确认。重启后可能看到旧记录或完整新记录：TRYING 回退，完整且已确认的 STABLE 保留。恢复提交再次失败时拒绝持久化挂载，不继续尝试执行。

## 选择记录

四个事务键仍是 `/notes/user`、`/slots/a.sfk`、`/slots/b.sfk`、`/boot/current`。最后一个键改为 160 字节的规范记录：

| 字节偏移 | 内容 |
| --- | --- |
| 0–7 | `SFUPD1\0\0` |
| 8 | phase：0 STABLE、1 PENDING、2 TRYING |
| 9 | 已确认槽：0、ASCII a 或 b |
| 10 | 候选槽：0、ASCII a 或 b |
| 11–31 | 全零保留字节 |
| 32–63 | 已确认包 SHA-256；没有槽时全零 |
| 64–95 | 候选包 SHA-256；没有槽时全零 |
| 96–159 | NUL 结尾且尾部补零的 app_id，最长 63 字节 |

app_id 只接受 ASCII 字母、数字、点、下划线和连字符。STABLE 不得有候选；PENDING/TRYING 必须有候选且不同于已确认槽。空状态不得有身份或摘要。未知 phase、非法组合、非零保留或尾部填充均拒绝。

已确认应用存在时，后续候选必须具有相同 app_id。候选包与状态在同一事务提交，试运行固定到该摘要；另一个正确签名包也不能直接替换它。旧版单字节 a/b 记录可读取：先认证所选包，导入为已确认状态，下一次安装写入新格式。错误的旧包不会被默认信任。

## 范围与验证

健康标准是当前有界命令应用的“按时退出 0”，不是长期服务的就绪、业务正确性或生产健康策略。成功确认后的程序在未来一次运行失败，不会自动撤回已确认版本。没有版本单调计数、密钥轮换、TPM 防回滚、系统/内核双槽或多应用管理。

回退只恢复应用选择器。控制台输出及未来可能加入的文件、网络、数据库副作用不能由选择旧包撤销；本阶段未提供跨应用数据事务或 schema 迁移保证。磁盘摘要不提供离线存储认证；攻击者恢复整份旧磁盘镜像的行为不在此防护范围内。

`tests/test_update.c` 把实际状态机与事务引擎组合，覆盖 stage/begin/confirm/rollback 四个提交点，各 261 个操作边界 × 三种故障模式，共 3132 个失败场景，并验证恢复记录与槽摘要一致、未确认尝试不能变成已确认版本。规范编码、截断、保留字段、身份、重复试运行和首装失败另有检查。

`tools/qemu_persist_test.py` 在 legacy 和 VT-d/modern 下分别验证实际应用页故障、退出 42、死循环超时、首装失败、待更新保护、身份/摘要/签名拒绝、旧格式迁移、非法状态拒绝、试运行期间终止 QEMU 后回退，以及应用退出 0 后确认写 EIO 不被误报成功。它们不等同于物理断电或任意硬件验收。
