# SpiritFoxOS 总体设计与实施规格

版本 0.1，2026-10-21。状态：开发提案，等待作者审阅，不是功能完成证明。
基线 upstream/main：`4a5196952ecc3dd049f14c004f284ac72cad2226`。

## 目标与兼容原则

精简核心机制，其余功能逐步由统一 `.sfmod` 模块承担；支持安全热插拔，资源通过文件
命名空间访问，原生 `.sfk` 应用由多个模块协作运行。保持现有 x86_64 UEFI、Linux ABI、
Shell、FAT32 和 Wayland 功能，一次迁移一个接口，回归通过后再撤除旧路径。
以核心职责、可信代码量和服务依赖衡量精简程度，不以改后缀或强行减少行数验收。
首要平台是 QEMU x86_64 UEFI；真机、BIOS、其他架构和完整 POSIX 单独规划。

## 核心与模块职责

最终核心保留启动交接、地址空间和页映射机制、线程上下文及基础调度、陷阱与 IRQ
转发、受控 IPC、不可伪造能力、资源回收、计时和最小故障日志。
物理页所有权与映射检查保持可信；内存策略和进程策略逐步外移。
VFS/文件系统、驱动、网络、图形、包管理、SFK 解析、Linux ABI 兼容、进程创建策略及
模块管理策略逐步进入模块。最小引导加载器和救援通路可留核心，逐项记录必要性。

```text
.sfk 原生应用 / Linux 兼容应用
                 |
文件 / 进程 / 运行时服务（.sfmod）
                 |
VFS / 文件系统 / 网络 / 图形 / 设备服务（.sfmod）
                 |
核心：线程、地址空间、IPC、能力、IRQ、时间
                 |
x86_64 UEFI / 硬件
```

过渡期保留逻辑边界，部分服务仍运行在核心内；隔离状态必须逐服务说明。

## `.sfmod` 与热插拔契约

沿用现行 ELF/SDK。模块身份包括名称、版本、ABI、依赖和服务协议版本；模块 ABI 与
服务消息版本分开管理。扩展必须同步 SDK、打包器、加载器、模块和不兼容拒绝测试。
模块之间只用公开消息接口，不链接对方私有符号，不把裸指针当跨服务协议。

目标状态机：DISCOVERED → VERIFIED → STARTING → ACTIVE → QUIESCING → STOPPED →
UNLOADED；失败转 FAILED 并回收本次资源。当前加载器尚未实现完整状态机。
先验证完整格式、边界、ABI、依赖图和配额，再初始化，最后发布端点。
初始化失败逆序回收，不可回滚的外设副作用必须另设恢复协议。

卸载停止接收新引用、撤销发现入口，等待或取消在途请求，释放 IRQ/DMA、定时器、
线程、映射和文件引用；确认无执行流后才释放代码。不能完成则返回 EBUSY。
根文件系统和关键引导服务可 pinned，拒绝普通卸载。
热替换先启动新实例、导入有版本的状态，准备完成后原子切换发现入口，旧引用清空后
回收旧实例；失败保留旧实例。旧句柄保留原会话或明确失效，禁止绑定到同名新对象。
服务实例带代数；内核机制本身不承诺任意热替换。

模块热插拔与物理设备拔插分别验收。未证明 DMA 停止、总线与 IRQ 引用撤销的 AHCI
服务保持不可卸载。第一步只做无硬件副作用、无依赖 demo 的重复装卸和失败回滚。

## 文件资源模型

统一命名、open/close/read/write/stat/readdir，并逐步增加 poll/ioctl/映射/事件。
对象可拒绝无意义的操作，例如不可 seek 的消息端点。短读写、EOF、超时、取消和服务
死亡必须有明确语义。共享内存传输须显式授予范围与寿命。
沿用 `/dev`、`/tmp`、`/run`、`/modules`；规划 `/proc` 进程视图、`/sys` 状态、
`/srv` 服务发现和 `/opt/sfk` 应用目录。新增路径必须实际接入后端。
句柄固定打开时的对象、权限和服务代数；同名重建不改变旧句柄身份。
路径规范化、组件边界、符号链接深度、长度和整数运算必须有界。
目录链接与打开引用分开计数，保留 dup/fork/exec/exit 生命周期。
动态挂载/卸载参与模块 quiesce，有打开引用时不得释放后端。

## `.sfk` 格式与执行链

`.sfk` 是原生可运行应用容器，包含元数据、服务/运行时需求、权限、资源及可执行载荷。
第一版载荷复用 ELF64，保持容器身份，不重新编写机器码链接格式。
安装和直接运行是两个入口；直接运行不隐式修改全局注册表或安装服务。

已有 `kernel/include/pkgmgr.h` 的 `SFK_VERSION=1` 和 packed `sfk_header_t`。
`SFK_MAGIC=0x53464B21` 的小端字节是 `21 4b 46 53`，不能仅按注释字符串判定。
现有 signature 字段不等于已实现签名验证。先审计并锁定 v1 布局和解析行为；
新增模块依赖或区段表若需 v2，应明确探测/拒绝/转换路径，不静默改变 v1。

未来规范须逐字段定义魔数/字节序、版本/头长、架构/总长、区段偏移和长度、包身份、
入口、模块/协议/运行时需求、权限、摘要和可选签名算法。使用固定宽度序列化与布局
断言，禁止依赖宿主 padding、size_t 或指针。先限定配额，再解析不可信输入。
区段做减法边界检查，拒绝重叠、越界、计数溢出、未终止字符串、重复身份和路径逃逸。
解析完成后才发生安装或执行副作用。

目标执行链（服务名为规划，尚未表示已注册）：

1. VFS 服务只读打开容器，固定同一内容快照。
2. SFK 服务验证头、清单和区段；依赖服务检查模块/协议/运行时，不自动下载代码。
3. 权限服务依据已授予能力收窄权限，声明不构成授权，缺必要权限则拒绝。
4. ELF 运行时检查载荷，进程服务创建独立地址空间、线程及受限文件句柄。
5. 监督服务发布 PID、退出码和日志；失败逆序回收，服务失效向调用者明确报告。

应用运行时保留服务引用，不能强卸载正在使用的运行时。`.sfk` 不等于内核插件，后缀
或签名不能直接授予 Ring 0。最终验收 hello.sfk 经多个真实 `.sfmod` 服务运行、输出并
退出，同时覆盖坏头、缺依赖、权限不足、服务死亡和失败回滚。

## 隔离与存储

先建立进程能力表、独立地址空间、可取消 IPC，再迁移非可信服务。IRQ 绑定/ACK、
DMA 范围/页固定、映射撤销均需显式授权。无 IOMMU 或等效保护不宣称任意 DMA 设备
完整隔离。服务崩溃由监督处理，重启不复活旧句柄；核心、根服务与应用分别定义恢复策略。
READ、WRITE 命令完成、flush 和事务持久化是不同保证。保留现有 FAT32 失败隔离；
新写服务先定义卷授权、顺序、完成计数和失败状态。破坏性测试只使用新建可丢弃镜像。

## 里程碑与验收

| 阶段 | 有界交付 | 必须验证 |
| --- | --- | --- |
| M0 | 设计、基线和工具复核 | 最终提交 Ubuntu/Arch 构建及 UEFI smoke |
| M1 | demo 运行期装卸与管理入口 | 100 次循环、旧句柄、依赖/忙拒绝、OOM 回滚、资源基线恢复 |
| M2 | 动态发现/挂载与引用协议 | dup/fork/exit、unlink 后存活、忙卸载拒绝、原文件功能 |
| M3 | SFK v1 解析审计、格式契约与打包检查 | 截断、溢出、路径攻击、固定向量、兼容行为 |
| M4 | 能力、隔离及 IPC 等待/取消/超时 | 越权拒绝、服务死亡唤醒、取消竞态和回收 |
| M5 | SFK/依赖/运行时/进程服务协作 | hello.sfk 与错误回滚、实际权限隔离 |
| M6 | IRQ/DMA、存储授权及恢复 | 每设备独立实测和断开/失败/重启语义 |

M3 纯解析可先于 M2；M5 隔离执行必须等待 M4。每轮只做一个可验收目标，优先真实
可复现缺陷和最小缺失契约，不同时重写调度器、VFS、SFK 和驱动。

## 持续开发流程

每五小时检查进行条件。先读额度/检查点，触限、额度不可读或任一窗口剩余不高于 5%
则保存并结束本轮，保留自动任务等待重置，不购买额度。修改、构建、提交/推送前复查，
预留收尾用量；不能保证触限时模型仍能运行检查。
确认无其他写入者/未归属改动，再 fetch、读取最新设计/integration/NEXT。
干净工作树只作安全快进同步；分歧/冲突不得 reset、覆盖或改写他人历史。
每轮先计划，实施后跑定向测试和必要回归。每次提交更新 integration 与 NEXT，
pre-push 对最终提交验证 Ubuntu/Arch。只推个人 Fork 分支，以 PR 交作者审阅，不自动合并。
DSH 只接必要复制文件及有明确范围的小任务，输出到独立目录，不直接改正式仓库、
提交、推送、安装或扩展任务。Codex 审查并独立测试，进程成功不代替验收。
保留 SHA、日志、实际验证、推送/CI 状态及下轮入口。无新结果静默；完成、失败或需要
用户处理时报告。无可执行事项结束本轮，用户喊停则停用自动任务。
