# 统一设备注册接口提案（尚未实现）

2026-10-19。当前普通 /dev 由旧 devfs 提供，null/zero 操作进入模块；
直接设备服务枚举只有两个节点。PCI 快照不负责发布 /dev 节点。

建议 dev.registry 管理标准化路径、设备编号、类型/模式、逻辑 owner 与后端引用。
第一步统一只读目录视图：旧适配器登记硬件节点，dev.tmpfs 登记 null/zero。
同名必须失败，不按登记顺序覆盖；消息不传回调、inode 或任意内核指针。

记录需版本/长度、owner、节点代数、路径、类型、major/minor、backend route/handle
和支持操作位。逻辑 owner 不是安全能力，当前 Ring 0 不能阻挡恶意代码；未来必须
由核心验证调用者身份，不能直接相信消息自报 owner。设备号也不是访问权限。
路径按组件验证，限制长度/深度/节点总数，拒绝点/双点与保留名。

建议 REGISTER、LOOKUP、READDIR、RETAIN、RELEASE、UNREGISTER，先评审布局和
错误语义。首版可以仅启动登记、禁止动态注销，必须明确返回不支持。
名字链接和打开引用分别计数；注销阻止新 open，旧节点存活到最后 RELEASE，
供应者失效 I/O 返回 ENODEV。同名重建不得复用旧引用，代数耗尽停用槽位；后端仍有
引用或调用时禁止卸载。动态生命周期实现前保留运行期卸载禁令。

公共 VFS 和服务目录应读取同一注册快照，旧 inode 操作先作为后端适配器，后续逐个
替换为消息驱动。命名空间更新与 open 取引用同步；短 RPC 临界区不能睡眠，未来
阻塞 I/O 需可睡眠引用协议，不能把当前自旋锁跨等待保留。

验收：两种枚举各节点只出现一次；重复、错误 owner/旧代数/坏路径/容量有测试；
注销不使已打开 inode 悬空，同名重建不命中旧引用；旧 AHCI、input/DRM、null/zero、
tmpfs 和 Wayland 回归保留。IRQ ACK、DMA、配置写与 Ring 3 隔离另行设计。
