# 统一设备注册：当前实现与后续提案

2026-10-19。启动期登记、封存、统一目录视图已实现，详见
[integration/20261019-device-registry.md](integration/20261019-device-registry.md)。
本文件保留尚未实现部分的设计建议，不将建议当作既定任务或完成项。

## 已实现

可信启动适配器验证并导入旧 devfs 的真实节点；dev.registry 管理规范化路径、逻辑
owner、节点/父句柄、类型/模式、后端编号和元数据。公共目录 readdir 与消息目录
共用此表；旧 dentry 树冻结为路径缓存，硬件 I/O 继续走原 inode/驱动。
null/zero 名称只绑定正确 dev.tmpfs 后端，实际数据调用继续通过消息转发。

最多 64 个节点含根、8 层、255 字节路径/63 字节组件。重复不覆盖，未知 owner、
错误长度/版本/路径/后端拒绝；记录不含内核指针。注册失败不发布节点。
封存后禁止名字空间增删、重新挂载/卸载；UNREGISTER 返回 ENOSYS，未实现热拔插。
运行期不提供卸载/替换服务入口。逻辑 owner 和设备编号都不是安全能力。

## 后续提案（尚未实现）

动态注销需将名字链接与打开引用分开：先阻止新 open，旧节点存活至最后 RELEASE，
供应者失效返回 ENODEV；同名重建不得复用旧引用，代数耗尽停用槽位。后端仍有调用
或引用时禁止卸载。硬件消息化前，不能将 registry 的 metadata RETAIN 当成真实驱动
实例的引用计数；当前硬件文件生命周期仍由 VFS/驱动负责。

未来核心应验证调用者身份/能力，不能相信消息自报 owner。对未知设备号不虚构
major/minor；PCI 物理地址也不授予映射权限。动态创建必须同步目录和 open 取引用，
阻塞 I/O 使用可睡眠协议，不能把当前短 RPC 自旋临界区跨等待保留。
IRQ ACK、DMA、配置写与 Ring 3 隔离须单独设计与测试，不能用注册表代替。
