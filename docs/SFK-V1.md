# SFK v1 文件头契约

本页锁定既有 `sfk_header_t` 的文件头布局，配套 `sfk_parse_header`。
仅覆盖文件头、区段外边界和包 ID，不代表元数据、安装器或原生执行链已安全验收。
SFK v1 与模块 ABI 1.5 分别管理；本轮不改变二进制布局或函数签名。

## 线格式

所有整数为固定宽度小端序；头长固定 1084 字节，没有宿主 padding。
字符串字段是定长字节数组，必须在各自容量内含 NUL；容量包含终止符。
除包 ID 外，本轮只验证终止，不验证字符串编码或规范化资源路径。

| 偏移 | 字节 | 字段 |
| --- | --- | --- |
| 0 | 4 | magic：`0x53464B21`，实际字节 `21 4b 46 53` |
| 4 | 4 | version：必须为 1，拒绝 0 和未来版本 |
| 8 | 64 | pkg_id |
| 72 | 64 | pkg_name |
| 136 | 32 | pkg_version |
| 168 | 64 | vendor |
| 232 | 256 | description |
| 488 | 32 | category |
| 520 | 128 | icon_path |
| 648 | 128 | exec_path |
| 776 | 4 | nperms |
| 780 | 4 | nreg_entries |
| 784 | 4 | nfile_assocs |
| 788 | 4 | nservices |
| 792 | 4 | ndependencies |
| 796 | 8 | data_offset |
| 804 | 8 | data_size |
| 812 | 8 | meta_offset |
| 820 | 8 | meta_size |
| 828 | 256 | signature：仅保留原始字节，尚无签名认证 |

包 ID 用作 `/opt/sfk/<pkg_id>` 和注册表中的单个路径组件：长度 1–63，
只允许 ASCII 字母、数字、`.`、`_`、`-`，且不允许单独的 `.` 或 `..`。
因此拒绝斜杠、反斜杠、控制字符等路径注入；不改变显示名称中的非 ASCII 字节。

## 区段与 API

`size` 是调用者保证可读的完整容器快照大小。数据和元数据区段各自使用以下规则：

- `(offset, length)=(0, 0)` 表示缺省区段。
- 其余描述符要求 `1084 <= offset <= size` 且 `length <= size - offset`。
  允许空区段位于头后或 EOF，拒绝落在文件头内的空区段。
- 两个非空区段不允许重叠，允许相邻、调换先后和中间填充；不强制占满文件。
  不用未验证的 `offset + length` 做加法边界判断。

空指针、短头、错误魔数/版本、字符串或区段不符合上述约束时返回 `-1`，输出头保持
原样；成功返回 0，再一次性发布解码结果。输入可以不对齐。调用者不得在解析过程中
并发修改输入。头声明的权限或 signature 字段均不构成授权或认证。

兼容性变化是明确拒绝旧实现曾接受的畸形头（含 version=0），有效 v1 布局保持不变。
仓库目前未找到 SFK 打包器或实际 `.sfk` 样本，兼容证据是固定字节测试，不能替代真实
第三方包验证。未来新增结构必须另行定义版本探测/转换，不静默扩充 v1。

## 验证与未完成项

`make test-sfk` 在宿主运行 ASan/UBSan 的固定向量：逐字节短头、不对齐输入、版本、
全部字符串、包 ID 路径攻击、64 位范围与溢出、重叠/相邻/缺省/空区段，以及失败不改输出。
已接入 `tools/check-linux.sh`，随 Ubuntu/Arch 最终提交检查运行。

计数只做小端解码，**尚未验证其与元数据内容的关系**；不可信元数据仍可能触发旧安装器
的问题。后续需统一有界游标、配额、可变注册表 value_data 的所有权/长度、服务区段定位、
所有记录的字符串和路径、声明权限与实际授权分离，以及安装副作用/回滚。
旧服务定位代码存在重复跳过注册表头的问题，注册表解析还会丢失变长值；本轮不把文件头
检查当成这些问题已经修复，不应据此启用不可信包安装。
