# SFK v1 解析契约

本页锁定既有 `sfk_header_t` 的文件头布局，配套 `sfk_parse_header`。
覆盖文件头、区段外边界、包 ID、权限与注册表记录；不代表全部元数据、安装器或原生执行链已安全验收。
SFK v1 与模块 ABI 1.5 分别管理；本轮不改变二进制布局或函数签名。

## 线格式

所有整数为固定宽度小端序；头长固定 1084 字节，没有宿主 padding。
字符串字段是定长字节数组，必须在各自容量内含 NUL；容量包含终止符。
除包 ID 外，本轮只验证终止，不验证字符串编码或规范化资源路径。

| 偏移 | 字节 | 字段 |
| --- | --- | --- |
| 0 | 4 | magic：`0x53464B21`，实际字节 `21 4b 46 53` |
| 4 | 4 | version：必须为 1，拒绝 0 和未来版本 |
| 8 | 64 | pkg_id |
| 72 | 64 | pkg_name |
| 136 | 32 | pkg_version |
| 168 | 64 | vendor |
| 232 | 256 | description |
| 488 | 32 | category |
| 520 | 128 | icon_path |
| 648 | 128 | exec_path |
| 776 | 4 | nperms |
| 780 | 4 | nreg_entries |
| 784 | 4 | nfile_assocs |
| 788 | 4 | nservices |
| 792 | 4 | ndependencies |
| 796 | 8 | data_offset |
| 804 | 8 | data_size |
| 812 | 8 | meta_offset |
| 820 | 8 | meta_size |
| 828 | 256 | signature：仅保留原始字节，尚无签名认证 |

包 ID 用作 `/opt/sfk/<pkg_id>` 和注册表中的单个路径组件：长度 1–63，
只允许 ASCII 字母、数字、`.`、`_`、`-`，且不允许单独的 `.` 或 `..`。
因此拒绝斜杠、反斜杠、控制字符等路径注入；不改变显示名称中的非 ASCII 字节。

## 区段与 API

`size` 是调用者保证可读的完整容器快照大小。数据和元数据区段各自使用以下规则：

- `(offset, length)=(0, 0)` 表示缺省区段。
- 其余描述符要求 `1084 <= offset <= size` 且 `length <= size - offset`。
  允许空区段位于头后或 EOF，拒绝落在文件头内的空区段。
- 两个非空区段不允许重叠，允许相邻、调换先后和中间填充；不强制占满文件。
  不用未验证的 `offset + length` 做加法边界判断。

空指针、短头、错误魔数/版本、字符串或区段不符合上述约束时返回 `-1`，输出头保持
原样；成功返回 0，再一次性发布解码结果。输入可以不对齐。调用者不得在解析过程中
并发修改输入。头声明的权限或 signature 字段均不构成授权或认证。

兼容性变化是明确拒绝旧实现曾接受的畸形头（含 version=0），有效 v1 布局保持不变。
仓库目前未找到 SFK 打包器或实际 `.sfk` 样本，兼容证据是固定字节测试，不能替代真实
第三方包验证。未来新增结构必须另行定义版本探测/转换，不静默扩充 v1。

## 权限记录与读取 API

权限请求从元数据区段首字节起连续排列，每条固定 164 字节：偏移 0 的小端 uint32 flag、
偏移 4 的 32 字节名称、偏移 36 的 128 字节描述；两个字符串必须各自包含 NUL，允许为空。
flag 按原值解码，不因解析通过而取得实际能力，不在本接口判断授权策略。

`sfk_get_perm_requests` 先验证头，再要求 nperms 不超过 `SFK_V1_MAX_PERMS=32`，且所有
声明记录能完整放入 meta_size；不能使用区段后的文件填充或载荷补足记录。32 对应原安装器
的既有容量，旧实现曾静默截断超量请求，现明确返回错误，不变更 v1 线布局。

所有声明记录的字符串都通过后，才复制 `min(nperms, max_perms)` 条。即使调用者只需要
一个前缀，后续畸形记录也会导致整个读取失败；错误返回 -1，输出保持原样。
NULL/0 只校验，成功返回 0；负容量或正容量配 NULL 均拒绝。输入可不对齐，复制支持重叠。
调用者须保证输入快照在校验期间稳定，以及输出存储能容纳声明的容量。

安装入口会在目录/注册表副作用前校验权限记录，包括显式 grants 和 DRYRUN 路径。
默认请求即授予的旧策略仍在，不能据此声称权限隔离已实现；其他元数据记录尚未统一校验。

## 注册表变长值与所有权

权限记录之后是 nreg_entries 条变长记录。每条先是固定 392 字节头：key_path[256]、
value_name[128]、小端 uint32 value_type 和小端 uint32 value_size，紧接 value_size
字节的值；下一条紧随其后，不加宿主对齐填充。key_path 必须非空，两字符串须在各自容量
内有 NUL；允许空 value_name。类型字段按原值保留，本轮只校验值的存储边界，不校验其语义。

每包注册表记录上限 `SFK_V1_MAX_REG_ENTRIES=64`，单值上限为后端已有的 4096 字节。
所有声明记录的头和值都须位于 meta_size 内；区段外填充不能补足记录。
超量/截断/未终止字段明确拒绝，不再返回已解析的部分前缀，不静默截断超长值。
这些配额限制解析工作和分配，不改变 v1 线布局或模块 ABI。

`sfk_get_reg_views` 完整验证权限前缀和全部注册表声明后，返回拥有的视图数组：每个
sfk_reg_view_t 含复制的头和借用的 value_data 指针。这是内核内部结果，不能序列化为协议。
调用者负责保持输入快照不可变且存活到消费完全部值，再 kfree 数组一次；不得单独释放
value_data。安装器使用私有快照，写值完成后先释放视图数组，再释放输入。

原 `sfk_get_reg_entries` 签名保留，但只返回头部数组，值并不紧跟返回的头；需要值的调用者
必须用视图接口。两接口失败时保持输出指针和 count 原样，空成功返回 NULL/0，成功数组
由调用者 kfree。OOM 在发布前返回失败，不泄漏中间数组。

安装器在 grants/DRYRUN、建目录和注册软件前解析全部注册表记录。后端开键/写值失败会
返回失败并回收本轮临时资源、关闭键；已经发生的安装副作用不回滚，尚无安装事务。
注册表路径授权、文件关联/服务/依赖串的整体校验和权限授权策略不在本轮范围内。

## 验证与未完成项

`make test-sfk` 在宿主运行 ASan/UBSan 的固定向量：逐字节短头、不对齐输入、版本、
全部字符串、包 ID 路径攻击、64 位范围与溢出、重叠/相邻/缺省/空区段，以及失败不改输出。
另有权限、注册表变长值及真实安装入口的准确写值、副作用/回收和 OOM 测试。已接入 `tools/check-linux.sh`，
随 Ubuntu/Arch 最终提交检查运行。

权限和注册表计数、长度及字符串已按上述规则验证，**其他元数据尚未统一校验**；
不可信元数据仍可能触发旧安装器的问题。后续需统一其余有界游标、配额、服务区段定位、
所有记录的字符串和路径、声明权限与实际授权分离，以及安装副作用/回滚。
旧服务定位代码仍有重复跳过注册表头的问题；已修复注册表值读取不等于所有元数据安全，
不应据此启用不可信包安装。
