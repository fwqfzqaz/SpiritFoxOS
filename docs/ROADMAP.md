# 后续路线

当前已从首轮启动闭环推进至 M5 的只读磁盘运行原型。下表保留剩余工作，不将设计目标标为全部完成。

| 阶段 | 已有基础 | 后续工作 |
| --- | --- | --- |
| M0 | 固定容器、CBOR、签名、IPC/BootArgs、打包检查工具 | ABI 冻结、独立清单 schema、兼容工具 |
| M1 | CPL3、独立页表、异常、单线程进程、抢占、能力 IPC | 优先级、通用受控映射、能力转移/派生撤销、动态配额 |
| M2 | 依赖、状态机、资源账本、拒绝忙卸载、受控重启和新旧代并存 | 完整生命周期 RPC、故障监督、超时取消、并发事务和状态迁移 |
| M3 | 用户态目录、RAMFS、管道、偏移、poll、控制台 | openat、挂载、符号链接策略、事件队列、proc/sys 适配服务 |
| M4 | 独立 sf-native、验证装载计划、hello.sfk、运行时租约 | 完整 PI/重定位、受限导入、参数环境、SDK、独立 sfexec/sf-process |
| M5 | 用户态 legacy virtio-blk、SFRFS1、从盘验证并运行模块与应用、挂载租约、缺盘与损坏恢复测试 | modern virtio、更多只读磁盘格式、独立文件系统 sfmod |
| M6 | 包验证、实际设备复位与固定 DMA 页、不可确认时保留资源 | IOMMU、设备隔离故障注入、持久化写入、包槽事务、断电恢复 |
| M7 | 独立故障域与服务协议基础 | 网络、图形、用户会话、多核、选定服务状态迁移 |

下一项是 M6 的持久化与恢复设计：先明确可验证的提交边界和错误模型，再实现事务写入。现有可信驱动与 QEMU I/O 错误测试不能替代 IOMMU、真实设备复位失败或断电测试。
