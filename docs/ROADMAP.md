# 后续路线

当前已推进至 M6 的有界事务盘与签名应用双槽原型。下表保留剩余工作，不将设计目标标为全部完成。

| 阶段 | 已有基础 | 后续工作 |
| --- | --- | --- |
| M0 | 固定容器、CBOR、签名、IPC/BootArgs、打包检查工具 | ABI 冻结、独立清单 schema、兼容工具 |
| M1 | CPL3、独立页表、异常、单线程进程、抢占、能力 IPC | 优先级、通用受控映射、能力转移/派生撤销、动态配额 |
| M2 | 依赖、状态机、资源账本、拒绝忙卸载、受控重启和新旧代并存 | 完整生命周期 RPC、故障监督、超时取消、并发事务和状态迁移 |
| M3 | 用户态目录、RAMFS、管道、偏移、poll、控制台 | openat、挂载、符号链接策略、事件队列、proc/sys 适配服务 |
| M4 | 独立 sf-native、验证装载计划、hello.sfk、运行时租约 | 完整 PI/重定位、受限导入、参数环境、SDK、独立 sfexec/sf-process |
| M5 | legacy 与受限 modern PCI virtio-blk、SFRFS1、从盘验证并运行包、挂载租约、存储失败恢复 | 通用 modern/virtio MMIO、更多磁盘格式、独立文件系统 sfmod |
| M6 | 显式写权、OUT/FLUSH、双银行事务、笔记、包 A/B、试运行确认与失败/中断回退、身份及摘要绑定、已确认版本软件下限与精确重装幂等、Q35 VT-d RAM DMA 隔离、真实读/写故障与驱动隔离、事务恢复 | IRQ/通用设备隔离、ACS/多单元、真实硬件断电、通用持久文件系统、长期服务健康策略、密钥轮换/撤销与可信防回滚 |
| M7 | 独立故障域与服务协议基础 | 网络、图形、用户会话、多核、选定服务状态迁移 |

后续优先补齐更完整的持久化服务和签名/更新策略，再扩展设备与运行时能力。QEMU 已验证的 VT-d 配置不能替代 IRQ 隔离、真实设备复位失败或物理断电验证。用户已授权额度充足时按本路线继续推进，不再需要每轮等待手动确认。
