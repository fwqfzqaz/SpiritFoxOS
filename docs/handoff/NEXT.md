## 下一步：兼容 FAT32 写入的 DMA 生命周期与失败语义

1. 先审计 blkdev_write 的全部调用方、AHCI 命令超时后的 DMA 所有权。原 FAT32 临时页
   写完即释放，控制器超时后可能仍访问；读取桥的永久 bounce page 并未修复原写路径。
2. 优先建立核心持有、按设备串行的写 bounce 缓冲与失败隔离，明确注册冻结、容量边界、
   中途失败、EBUSY 的处理；先补故障注入。没有复位协议前，不复用可能仍被 DMA 访问的页。
   不直接给现有所有模块开放任意盘写权限；先决定卷/设备访问范围与调用接口。
3. 兼容写路径会在部分成功/目录更新失败时吞掉错误；新簇分配、清零、链链接、目录项更新、
   FAT 镜像一致性需分别审计。读取 FAT 表失败已经不再当作 EOC，不得回退旧错误语义。
   先交付可核验的失败传播/内存生命周期，事务与断电一致性另立验收，避免一轮混改。
4. 若新增 WRITE 消息/平台 API，按实际变化提高 ABI/协议并重编全部模块、包，补旧版拒绝
   测试；只有内核私有适配器变更时不要无理由升级 ABI。保留现有 READ 的错误清零与快照规则。
