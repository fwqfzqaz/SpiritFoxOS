## 下一步：只读块设备清单服务

先 fetch 并检查作者的新代码/对接文档及 PR 是否已合并。若仍开放，继续个人 Fork 的
现有 PR；如果作者已有接口，优先对接，避免建立重复协议。

建议新增 dev.block 的只读清单协议：版本/记录大小、代数快照、逻辑索引、名称、
设备类别与扇区数/扇区大小。先审计 blkdev_t 的真实语义和生命周期，不暴露内核指针，
不把未检测到的几何信息写成已知。不在本轮顺带开放块写入、DMA、IRQ 或热卸载。

当前模块包在 AHCI/ramdisk 前启动，块清单不能在模块 init 时静态读取：
应在存储探测完成后执行一次有界登记/封存，再对外提供 ENUM/GET；未封存查询须
明确返回“未就绪”。核对真实 blkdev 列表，并保持现有 FAT32/原始块读写路径。
新核心 API 如需增加，统一提升 ABI、打包器和全部模块/宿主畸形版本测试。

设备目录中的块节点目前仍是原 devfs 数据路径；不要把“有清单/有节点”写成块设备
消息读写已经迁移。dev.registry 的动态增删仍禁止；后续须评审引用、代数和提供者失效。
