## 下一步：让 FAT32 的实际读取使用只读块消息桥

先 fetch，检查作者是否合并/新写对接文档；优先适配作者接口，避免重复建设。
本轮启动自测已实际读取首/末扇区并与原驱动比较，但 FAT32 普通读还没迁移。

1. 审计 FAT32 中 blkdev_read 的调用上下文、LBA/扇区大小、缓存和锁；确认新增桥不构成
   消息递归。dev.block 后端只到物理块驱动，不得回到 FAT32/VFS。
2. 设计有界客户端，拆分超过 4096 字节的读取，验证每段响应 snapshot/长度/结果。
   段失败时调用方不能解析未完成或旧缓冲内容；明确 EBUSY/EAGAIN 的处理，不能在
   已关中断或持锁场景无限重试/睡眠，也不能无声绕回未校验的原始读取。
   原直接块读取者的超时 DMA 缓冲回收尚未统一解决，迁移时须一并核对该生命周期。
3. 先迁移只读 FAT32 盘路径，并在真正读取程序/文件时给出可核验标记；原写路径单独
   说明，不能把只读消息接口描述成写入迁移或磁盘写保护。
4. 通过故障注入确认忙、失效快照、短响应、坏长度、跨段错误不会让 FAT 解析旧数据。
   API/协议变更时同步版本、包、全部模块和拒绝测试；无必要不继续增加平台权限。
