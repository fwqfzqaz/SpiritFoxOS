所有模块仍为可信 Ring 0，无热插拔、监督重启或用户态故障隔离。

## 下一步：核实块设备容量与边界，再提供只读扇区消息

先 fetch/检查作者的新对接文档及 PR 合并状态，以最新接口为准。
新清单已具备 slot/snapshot，但暂不能直接当成任意扇区访问的权限。

1. 审计原 AHCI IDENTIFY 和 ramdisk 的容量/内存后端。AHCI 读取失败目前填默认
   2048 扇区；ramdisk_create 对多页连续性的注释承认其假设。须先验证并修正实际
   缓冲区/扇区边界，保留已注册设备行为，避免清单与读写后端不一致。
2. 明确定义“驱动报告、已确认、未知”的几何来源；如需修改 blkdev 结构或注册接口，
   一次更新全部调用者，加入失败/溢出/越界测试，不能把默认容量当探测成功。
3. 然后设计 dev.block 的只读 READ：必须验证 snapshot/slot、LBA/数量/乘法，单次
   响应不超过 4096 字节；拒绝未就绪/未知容量，不暴露指针，禁止写盘。
   底层硬件读仍可由受控核心适配器调用旧驱动；这并不等于 IRQ/DMA 或驱动隔离已完成。
4. 若核心 API 表新增块读入口，统一升 ABI、包版本、SDK、全部模块和版本拒绝测试。
   不支持动态卸载/热插拔；冻结清单后不能悄悄复用旧块槽。
