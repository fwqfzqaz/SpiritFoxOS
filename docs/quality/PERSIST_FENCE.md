# Persist 准入围栏：宿主与真实访客专项

本草稿只增加 Root 内部的准入作用域。Persist、Fs、块驱动继续运行，原挂载投影、
驱动租约及资源账本保留，104 仍是只读瞬时查询。没有停止/启动、公共操作码或
bootstrap 信任例外。管理员诊断已组合到作者 S4/P1 基线，当前四启动 E2 已通过；
完整、发布与托管仍独立验证，当前状态见 [PROGRESS](../project/PROGRESS.md)。

`sf_persist_fence_begin` 要求健康且允许准入的存储、已排空的 Fs 资源、存活的
Persist、完整 Root 信任缓存，以及没有 Root 装载作用域和未知写。函数在实际
104 往返之前发布单调递增的所有者令牌，随后再验证上下文。嵌套获取不会覆盖
已有所有者输出，计数耗尽拒绝而不回绕。

同一个围栏在实际拥有者入口拒绝 `/disk` 与 `/persist` 的新挂载描述、Root 包快照、
普通 Persist RPC、新装载与事务、原始块变更/控制、驱动/挂载/命名空间恢复及破坏性
诊断，不仅检查控制台文字。命名空间前端还在发送 IPC 前拒绝初始化、挂载发布和
卸载，避免错误地丢失原健康连接。RAMFS、控制台、管道、合法关闭与已知租约释放
保持可用。

前端所有后端设置函数也必须在本地绑定修改之前拒绝：清除/替换挂载钩子、外部
读写/截断和投影后端都不能发送 BACKENDS。返回值仍是原 reader 或原 void 语义，
绑定保持原值。ASSIGN/PROJECT/PROTECT 等管理操作同样在前端本地拒绝，避免把
正常围栏拒绝误当成命名空间连接丢失。

Root 原始命名空间交换入口另有默认拒绝的允许列表，只放行普通文件/RAMFS 操作
与只读 mount-check；INIT、BACKENDS、管理配置、挂载事务、UNMOUNT、全部 Fs
磁盘/生命周期和未知控制帧在 transport 字段修改与 IPC 之前拒绝，不能绕过前端。
CREATE 只允许 FILE/DIR/PIPE/CONSOLE，禁止创建不带挂载标签的 DISK/PROJECTION
后端节点。即使存在之前创建的无标签 DISK 别名，Root external_read 与真实 Fs
使用的 STORAGE_LIVE 回调也在围栏期间拒绝磁盘读取；元数据和合法关闭仍可继续。
正常初始上下文仍由可信 Root 安装挂载钩子和内置投影，本作用域不修复既有错误配置。

`sf_persist_fence_cancel` 必须持有当前准确令牌，并验证原 Persist/Fs/驱动身份、
端点原件、管理器代次、容量、挂载准入、健康且排空的账本和完整运行期信任快照。
它只取消自己的准入作用域，不卸载或修复状态。上下文变化或不健康时保持围栏；
零、错误、过期或重复释放的令牌不能重新开放准入，旧令牌也不能释放后来的作用域。

非嵌套的获取在本地预检失败时将输出置零。已经获取后，远端观测失败会尝试安全
取消；若上下文变化使取消失败，则返回原错误并保留**非零所有者令牌**。调用者必须
保留令牌并报告失败，没有强制释放/重启接口。原 uncertain_commit/DIRTY 和信任
故障不会被清除；不得通过重置信任缓存或丢弃旧实例制造健康上下文。

实际 Root 装载入口从包验证直到进程生成完成都持有独立所有者作用域，防止中途
获取围栏；普通 package_get 也在围栏期间拒绝新权限。原引导、签名、撤销和必需
同步规则保持不变。

## 已有证据与边界

E1 使用实际 storage/client/manager/namespace 函数，仅以有界替身模拟系统调用和
IPC 边界，并保留客户机完整位宽的 RUNNING 哨兵。它检查实际挂载描述、dup/reap、
每类 Fs 资源、104 往返中重入的准入、原始/管理入口、异常/丢失回复、令牌所有权与
耗尽，以及实例、信任和未知写上下文变化。前端和实际 package_get 回归另外检查
IPC/I/O 之前的本地拒绝。宿主套件与发布登记明确标注 E1 host only。

隔离宿主验证通过：围栏 3318 项、前端 243 项、WRITE ACK 693161 项、元数据
16821 项、静默查询客户端/解析器 386 项及实际卷 22713 项、信任同步 1003 项、
实际 package_get 92 项。四个 Root 源文件也编译为隔离宿主对象；该源码检查抑制了
原客户机/Windows 位宽差异诊断，不能作为生产 freestanding 构建证明。

编译、缓存和只读夹具副本均在此工作树 `.cache`。最终复核复制并校验 Root 的未
适配 Rust 库，只适配并链接私有副本，没有映射共享适配库；Root 工具链与生成的
公共头文件只读后缓存为私有副本，后续复核只使用这些私有输入。原始记录位于
工作树 `.cache/fence-e1/results.json` 和
`.cache/fence-e1/private-library.json`，均不进入版本库。

其中 43 次原始控制帧拒绝核对帧本身、transport、实际 namespace_control 状态、
投影节点、资源账本与信任不变，取消仍须成功；另有 34 次实际命名空间对端操作，
覆盖围栏中的普通 FILE/DIR/PIPE/CONSOLE 以及取消后的正常控制对照。前端遍历
清除/替换等 14 种尝试，并逐一核对所有原回调及零 IPC。两个原缺陷还使用固定
0a0867d 拥有者源码复现失败，记录于 `.cache/fence-e1/regression-baseline.json`；
原始卸载复现明确到达了模拟发送/接收边界，修正版则在发送前拒绝。

上述独立来源批次只有 E1。当前组合的生产源码 c0487d7 已完成初始构建/全宿主，
171.31秒通过，实测围栏3318项、前端243项、控制台676项。随后仅修改 E2 脚本的
完整登录期望行和失败清理，保存了首次失败日志；九份输入摘要已重新绑定。
七份生产产物及所有生产输入逐字节保持，未把旧脚本的失败计为通过。

当前9329d9d脚本的真实 E2 已完成：legacy/modern 双传输共四次启动，四个健康
状态/传输单元、两次真实未知 DIRTY 和两次生产恢复均通过。之后才讨论终止接受、确认死亡、私有
候选实例启动及保留投影的激活；本草稿没有实现这些停止/启动前提。E3 真机和 E4
掉电证据仍是独立缺口。

## E2 诊断与客户机结果（2026-11-16）

`persist-fence-test healthy|unknown` 只允许管理员会话，令牌保存在单次调用局部，
不接受外部令牌、不提供强制解除或服务替换。healthy 通过真实 Fs 打开/dup/关闭
挂载描述，检查排空、装载作用域、嵌套/伪造/陈旧令牌、104 与正常取消；围栏期间
尝试后端 setter、前端生命周期和原始 BACKENDS/UNMOUNT/FS_STOP，要求拥有者在
IPC 前拒绝。CREATE 的 DISK、PROJECTION 和非法模式同时从前端和原始入口拒绝。
普通 RAM 文件、投影与已有 echo 继续工作，新 bundle 装载被拒，取消后恢复实际
bundle 执行和磁盘/笔记读取。指纹、信任、Fs/驱动/管理器实例和客户机整盘逐项保持。

源码依赖另一审阅分支 `4960b4236bf52646506b79c8966ac98a85b879c7` 完成的 setter、
原始控制和 CREATE 类型/磁盘回调拥有者修复。
独立来源分支不能单独运行；当前组合已包含这些修正。诊断的 `/tmp` 父目录显式
申请写权以清理自建 RAM 文件，不放宽底层目录能力检查。
已有未打挂载标签 DISK 别名的详细路径由拥有者 E1 覆盖；新诊断只核对 disk-live
拒绝及禁止创建入口，不创建无法通过现有 NODE_FILE unlink 清理的 DISK 测试节点。
