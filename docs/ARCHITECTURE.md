# 模块化迁移设计

状态：经用户选择，先交付保留现有功能的过渡版本。本文区分当前实现和后续目标，
不把动态加载的内核代码称为具有故障隔离的微内核服务。

## 设计决定

参考规格提出的方向是：核心只提供机制，文件系统、设备、进程策略通过消息协作。
当前系统的 VFS、调度器、Linux ABI、DRM 和驱动之间已有大量指针和同步调用。
直接删除或移动这些代码会同时失去现有启动和用户程序，且难以定位回归。

选择增量迁移：新增独立的 `kernel/core` 机制层和 `modules` 服务；原 `kernel/src`
继续负责兼容路径。先验证 ELF 模块、依赖和统一消息文件协议，再逐个替换调用方。
旧代码保留在原路径，Git 保存历史；不复制一份易失去同步的 `legacy` 目录。

备选方案是立即重写全部内核，或只把原函数包装成模块注册项。前者回归范围太大，
后者没有建立真实的服务边界。本阶段使用真正独立链接的 ET_REL 模块，提供可以
在后续更换为跨地址空间传输的消息协议。

## 规格修正

- 参考模块头各字段合计 96 字节，不是 64 字节。ABI 使用固定宽度字段、头大小和
  `_Static_assert`。初始化函数放在重定位后的入口 section，禁止含糊的文件偏移。
- 参考消息字段合计 32 字节；本实现明确补足为 64 字节，载荷至多 4096 字节。
- 端点和文件描述符使用带代数的句柄，销毁后旧句柄不能命中新对象。文件操作仍须
  检查长度、偏移、操作类型和资源有效性，不能通过编码句柄跳过验证。
- `.sfmod` 是受信任的 Ring 0 插件。权限声明用于加载策略，不是硬件安全边界。
  非可信模块、驱动崩溃隔离需要 Ring 3、独立页表及受控 IPC/设备访问，后续实现。
- UEFI 已运行在 64 位模式；保留现有 EFI stub 和 GPT/ESP 镜像。BIOS/ISO 并非
  本阶段已支持的输出，不把替换镜像容器当作模块化的前提。

## 目标结构与迁移接口

2026-10-19 启动顺序：`init_core`（页分配/MMU/原 PCI 缓存）→
`init_hardware`（CPU/GS、APIC、时钟，尚未开中断）→ `init_allocators`
（仅一次 kmalloc/slab）→ `sfm_boot_early`（内嵌包、端点、PCI 快照自测）→
AHCI/ramdisk → 块设备清单登记/冻结/核对 → 根 VFS/FAT32 → 进程/syscall/系统服务 →
`sfm_boot_filesystems`（消息文件自测及 /modules、/tmp、/run 挂载）→
目录/input/DRM → 统一设备登记/自测/封存 → 开中断及 PID 回归 → 用户程序。
模块包来自链接进内核的只读数据，早期 init 只依赖内存、日志、消息和 PCI 缓存，
不访问待初始化的磁盘、旧 VFS 或进程。后期不得再次初始化分配器或加载启动包。

AHCI 控制器查找已走 `dev.pci` 的 FIND 消息；命令提交、DMA 和端口探测仍在原驱动。
无可用控制器返回空结果；协议失败单独报负错误，不退回原始 PCI 扫描。
平台启动阶段重复或乱序、包/自测/挂载失败会 panic，停止继续启动。
包加载失败仍由 loader 逆序回收；挂载开始后尚无事务回滚，失败直接停机，不重试。
细节和验证见 [早期 PCI/AHCI 对接](integration/20261019-early-pci-ahci.md)。

`dev.block` 在早期只建立空端点，ENUM/GET 返回 EAGAIN；存储探测完成后由核心发送
有界 REGISTER/SEAL，再逐项核对真实 blkdev 列表。清单不包含函数/驱动指针，不改变
原始块读写或 FAT32。AHCI/IDE 几何标为未确认，因为旧驱动可能使用默认容量；
ramdisk 的大小来自其软件缓冲区。详见 [块清单对接](integration/20261019-block-inventory.md)。

```text
UEFI stub -> kernel/src 的现有硬件/内存/进程初始化
                    |
              kernel/core/module
              验证内嵌模块包 -> 依赖排序 -> 重定位 -> init(api, owner)
                    |
              kernel/core/ipc
              带代数端点 / 有界队列 / 同步请求响应
                    |
          +---------+----------+
          |                    |
      demo.hello            fs.vfs
                               |
                           fs.tmpfs

现有 syscall -> 现有 VFS/驱动（兼容路径，本阶段保持）
                    |
                    +-> /modules、/tmp、/run 兼容桥 -> 消息 fs.vfs -> fs.tmpfs
                    +-> /dev/null、/dev/zero 节点 -> 消息 fs.vfs -> dev.tmpfs
下一阶段 syscall -> 文件消息 -> fs.vfs -> 更多文件系统/设备服务
最终阶段 Ring 3 服务 -> syscall IPC -> 核心端点/调度机制
```

模块只通过 SDK 的核心 API 表调用日志、内存、端点和消息接口；模块之间不链接
对方内部符号。模块 ELF 不依赖宿主 libc，所有未定义强符号均被拒绝。
依赖由包清单声明，元数据也记录依赖并核对；按满足依赖的顺序初始化。
缺失依赖、循环依赖、重名、ABI 不匹配、坏重定位必须在执行入口前失败。

核心持有模块状态、分配区间和端点。模块状态为未加载、已验证、已启动；
初始化失败回收端点和分配空间。卸载检查依赖和未结束调用，先 exit 再释放代码。
当前启动期间串行加载；运行期装卸不从任意 CPU/中断入口调用。

消息结构不传内核指针。文件协议包含操作、资源句柄、偏移和字节数，响应返回
有符号结果和数据。fs.tmpfs 提供有容量上限的目录树、读写、查询、符号链接和删除，
命名链接与打开引用分开计数；删除后旧打开文件可继续访问，重建同名文件得到新节点。
fs.vfs 的固定启动挂载表为 /modules、/tmp、/run 分配独立根，并将 /dev 路由到
dev.tmpfs 的 null/zero 服务。ABI 1.2 显式携带后端编号；尚无动态挂载协议。
dev.registry 在 input/DRM 初始化后导入真实节点并冻结，公共 /dev 与消息目录枚举
共用注册表；只有 null/zero 数据进入模块，其他设备保留原驱动与路径。
兼容桥保留路径查找缓存，目录枚举由模块消息提供。页缓存和磁盘事务另行迁移。

## 阶段及验收

1. **环境及可启动基线**：Ubuntu/Arch 分别全量编译和 QEMU UEFI 验证；修正 EFI
   格式、内核栈破坏等阻塞问题。保留固定版本的 musl、libffi、Wayland。
2. **模块化基础（已交付）**：64 字节消息、端点队列、请求响应、SDK、受限 ET_REL
   加载器、内嵌启动包、依赖验证；加载 hello、tmpfs、VFS 模块并执行实际消息文件
   创建/写/读/删除测试。畸形包、ELF 边界和重定位由宿主测试覆盖。
3. **兼容路径迁移（进行中）**：/tmp、/run 已接入消息 tmpfs，支持目录、枚举和打开文件生命周期；null/zero 已接入 dev.tmpfs；dev.pci 提供只读快照，Bochs 设备选择已走消息，硬件数据面尚未迁移。按 devfs、PCI/AHCI、
   tty、进程/Linux ABI 顺序迁移；每个设备实际启用后才登记为已迁移模块。
4. **隔离微内核**：分离线程与进程策略，IPC 阻塞/唤醒与取消，地址空间能力、
   IRQ 消息/ACK、DMA 约束、Ring 3 驱动监督及故障重启；最后扩展 SMP。
5. **扩展功能**：ext4、网络模块、页缓存及硬件覆盖；独立评审磁盘写入正确性。

当前不宣称阶段 3–5 全部完成，不为达到行数目标删功能，也不以“模块已登记”替代
实际迁移。buddy 分配器替换、APIC/SMP 重构应有独立压力测试，当前沿用现有实现。

阶段 A 的具体处理是复用现有 EFI、物理页分配、四级页表、IDT/APIC 和串口；
先修复实测故障并锁定启动测试，新增机制只依赖这些接口。后续将内存管理、
线程与中断原语逐一移到 core，每次移动保持原入口兼容，不同时改动算法和路径。

## 测试与限制

宿主检查模块 ABI、ELF 边界、section/符号/重定位及依赖错误；QEMU 启动必须出现
模块消息与目录测试标记，再通过 `/modules`、`/tmp`、`/run` 兼容桥验证用户态普通文件调用、独立根、截断/追加、删除后继续读写和节点回收，最后验证原 shell/autorun/Wayland。测试出现用户态
异常同样失败。Ubuntu 与 Arch 使用不同 GCC/NASM 的实际构建产物分别启动。
推送钩子验证提交快照，CI 同时验证两个发行版。

当前 ABI 的同步 call 是有界的内核内 RPC，不声称提供跨线程同步切换或超时。
异步 send/recv 是有界非阻塞队列，满/空返回错误，不丢弃消息。加载器不接受
外部不可信二进制，不提供签名验证。扩展 ABI 必须提高版本或头大小并补兼容测试。

设计参考：[seL4 IPC](https://docs.sel4.systems/Tutorials/ipc) 和
[fault handlers](https://docs.sel4.systems/Tutorials/fault-handlers.html)，
用于区分端点通信与故障隔离的责任；本项目未复制其实现，也不声称等同 seL4。
