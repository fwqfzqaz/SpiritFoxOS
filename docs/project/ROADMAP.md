# 路线图与 v0.3 执行计划

更新日期：2026-11-12。当前项目是可启动的 x86_64 UEFI 微内核原型：Core 0 已具备隔离、抢占、SMP/线程、能力 IPC、设备与 VT-d；文件系统、持久化、native 运行时、网络与账户会话已在 ring-3 服务中运行。阶段编号只表示纵向切片，不代表整体完成度。

长期目标与 `v0.4`–`v1.0` 的验收定义见[目标纲要](GOALS.md)；本文件负责 M0–M7 阶段基线与当前 `v0.3`（目标纲要 G0）的执行拆解。两者冲突时，目标口径以 GOALS 为准，当前事实以 STATUS 与代码为准。

本文件分两部分：前半部分保留 M0–M7 阶段基线，后半部分定义 `v0.3` 的目标、优先级与验收条件。

## 下一阶段方向：v0.3 模块化收尾与运行时加固

### 阶段目标

把「可演示的纵向切片」收敛为「边界稳定、可重复验证、可交给他人开发」的原型：

1. `sf-init` 只保留引导、策略与外壳职责，文件与持久化能力全部下沉到独立服务进程。
2. 在既有安全边界内扩展应用可用接口，而不是引入完整 POSIX 或通用动态链接。
3. 建立真实硬件与故障注入下的最低可靠性证据，并固定 ABI/文档同步规则。

### P1：有界应用接口与 ABI 稳定性

在「单一认证 POSIX 运行时库、最多 32 项导入/64 项导出、最多 8 个映射段」约束内扩展能力：

- 补齐常用只读/只写文件语义：`stat` 类元数据、目录遍历游标（2026-11-12 完成）、`getcwd`/路径规范化、错误码一致性。
- 为导入/导出表增加宿主编译期检查与缺失导出的 QEMU 负例；ABI 快照只允许追加并显式审阅。
- 评估 `malloc` 之外的替代方案：如需动态内存，优先在应用内提供有界 arena SDK，而不是让运行时库持有全局状态。
- 不引入多库依赖、符号版本、TLS、惰性绑定或完整 POSIX；确需突破时必须先更新设计说明。

完成定义：

- 新增接口均有宿主断言 + 至少一次真实访客测试。
- ABI 快照差异、导入/导出表、文档三处一致。
- 现有应用与模块二进制无需重签即可继续运行（只追加，不破坏）。

### P1：服务可靠性最低证据集

- 生命周期 RPC 覆盖命名空间、持久化与文件服务的启动/停止/重启；验证在途请求与取消边界。
- 为每个 ring-3 服务增加故障注入：进程死亡、超时、回复丢失、磁盘 EIO、网络中断。
- 固定「服务不可用时的降级行为」：控制台保持可用、bundle 应用可回退、磁盘只读挂载可存活。

完成定义：

- 每类故障至少一个可重复的 QEMU 场景，并记录预期错误码与恢复路径。
- 文档明确「已验证 / 未验证」边界，不用 QEMU 结果替代真实硬件结论。

### P2：设备与图形纵向切片

- 在现有 virtio-blk/virtio-net 基础上评估 virtio-input 与 framebuffer 输出；驱动仍为 ring-3 `.sfmod`。
- 图形优先做「帧缓冲 + 输入事件 + 一个有界合成器」的最小闭环，不承诺桌面环境。
- 保留 headless / 串口 / VNC 回退路径，确保无图形后端时测试仍可运行。

完成定义：

- 至少一个 QEMU 场景完成「输入事件 → 应用消费 → 帧缓冲更新」闭环。
- 设备仍通过 PCI 探测、IOMMU 窗口与 IRQ 授权接入，不绕过既有隔离。

### 明确不做（本阶段边界）

- 通用可写文件系统、完整 POSIX/libc、多库动态链接、TLS、完整图形桌面。
- 真实生产信任根、Secure Boot 防回滚、可信计数存储。
- 未经验证的硬件通用性承诺；所有设备结论以实际测试配置为准。

## 优先级与执行顺序

1. P0 拆分（先做命名空间/RAMFS 下沉，再做策略分层）。
2. P1 ABI/接口扩展与服务可靠性并行推进，二者都必须附带回归。
3. P2 设备/图形在 P0/P1 稳定后启动，避免同时扩大边界。

每轮工作遵循以下门禁：

- 宿主测试 `python3 tools/test.py --host-only` 通过；
- 涉及内核、ABI、QEMU 行为时，完整 `python3 tools/test.py` 通过；
- ABI 快照仅追加并有审阅记录；
- 文档（STATUS/ROADMAP/对应架构文档）与代码同步；
- Linux 与 Windows CI 均为最新提交通过。
