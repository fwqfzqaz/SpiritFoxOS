更新日期：2026-10-24。当前是可启动的 x86_64 UEFI 微内核原型，路线已涉及 M0–M6；各阶段仍有未完成项，阶段编号不代表整体完成率。

## 现在能做什么

UEFI 引导进入 Core 0 与隔离用户态，提供能力 IPC、抢占、进程/内存和浮点上下文隔离。用户态管理器可装卸模块、固定依赖代次并监督 echo/native；提供 RAM 文件/目录、受控只读目录委派和 virtio 磁盘访问。签名应用支持 argv、显式环境与受限位置无关装载；持久化原型提供笔记、一个应用的 A/B 更新、健康确认/失败回退、软件版本下限和密钥撤销。

## 还差什么

| 阶段 | 当前基础 | 主要缺项 |
| --- | --- | --- |
| M0 格式与 ABI | 容器、CBOR、签名、IPC/BootArgs 和工具可用 | ABI 冻结、独立清单 schema、兼容工具 |
| M1 内核 | 单核、隔离、抢占和能力端点 | 优先级、动态配额、通用映射、能力传递与派生撤销 |
| M2 服务管理 | 依赖、租约、受控重启及 echo/native 有界监督 | 完整生命周期 RPC、通用健康/挂起监督、取消、并发事务与状态迁移 |
| M3 文件与命名空间 | RAMFS、目录句柄、元数据、只读委派和受控挂载 | 通用授权/撤销、进程挂载视图、符号链接、事件队列、proc/sys 服务 |
| M4 应用与 SDK | native、argv/环境、受限 PI 与文件客户端 | 受限导入、完整 SDK、独立 sfexec/sf-process、异步/取消协议 |
| M5 存储设备 | 受限 legacy/modern virtio-blk 与 SFRFS1 | 更多设备/传输、通用磁盘格式、独立文件系统模块 |
| M6 持久化与安全 | 双银行、A/B、版本/签名/撤销及旧盘兼容 | 通用持久文件系统、IRQ/通用设备隔离、ACS/多单元、生产根、可信防回滚与真实断电验证 |
| M7 扩展系统 | 独立故障域和协议基础 | 网络、图形界面、用户会话、多核和选定服务状态迁移 |

## 验证边界与下一步

当前事务卷仍是最多五个文件、每个上限 16 KiB 的原型，面向笔记和一个应用双槽；文件 SDK 不等于通用文件系统。native 没有动态库、TLS 或完整导入支持；PI 基址选择不是安全随机化。设备隔离仅覆盖已测试 Q35/单设备范围，QEMU 结果不替代真实硬件/IRQ/断电验收。
