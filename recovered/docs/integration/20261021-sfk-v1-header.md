## 问题与改动

旧 `sfk_parse_header` 仅检查魔数及版本上限，会接受 version=0、越界/重叠区段、未终止
字符串和含路径穿越的包 ID。先复制到输出再验证，也会在失败时修改输出。

将同名函数移入独立 `kernel/src/services/sfk_header.c`，仍由现有调用者使用。
锁定 1084 字节布局、显式小端解码和不对齐输入；精确接受 v1，检查全部头字符串、
单组件包 ID 和两个区段的外边界/重叠，失败保持输出。规则及兼容变化见
[SFK v1 契约](../SFK-V1.md)。不改变 `.sfmod` ABI 1.5、v1 字段或函数签名。

新增 `make test-sfk`，纳入 `tools/check-linux.sh`，在 Ubuntu/Arch 的最终提交检查
中执行；不增加第三方依赖。原 Makefile 发现源码规则会自动编译新文件。

## 限制与下一步

这是 M3 的文件头子目标，不是完整 SFK 验证器或安装安全证明。计数尚未与元数据记录
逐项验证；旧注册表解析的变长值所有权、服务定位的重复跳过、默认声明权限即授予等
问题仍待后续独立修复。payload、摘要/签名、配额、安装事务和运行链均未实现本轮验收。

本轮固定向量确认线格式，但未发现实际 SFK 样本/打包器；更严格拒绝畸形输入的行为
有明确定义，不宣称所有外部历史包均兼容。下一轮优先有界元数据游标与完整解析后再产生
副作用，先写针对旧缺陷的回归，再设计原生打包器；不扩展到调度器或硬件驱动。
